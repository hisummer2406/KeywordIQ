# V2 只读诊断

输入：症状、发生时段及其时区、request_id（如有）、站点/日周期次、已授权目标与可用访问方式。
先复用已有证据；缺少不可替代的定位信息时一次问清，不因缺SSH就把远端当正常。

## 确认范围

- 先读 [生产交接](../../../docs/ops/v2-ecs-handoff.md)、[运维规则](../../rules/operations.md) 和
  [观测手册](../../../etc/observability-runbook.md)。入口/目录按当前交接核实，不照抄V1端口。
- 使用已授权的读取渠道，标明本机、V2容器、代理、外部服务与数据库分别得到什么证据。
- 不打印.env、令牌、完整连接串、原始个人数据或带秘密的日志；摘要保留request_id与必要作用域。
- 无对应访问能力时停止该层检查并报告“未验证/访问受限”，不猜原因、不升级成“服务正常”。

## 采证路径

1. 核时间与请求是否到达代理/应用，按request_id对照两层有限日志，区分客户端、代理、应用和后台任务。
   completed仅表示响应发完，不等于业务成功；按HTTP状态及业务错误码判断。
2. 如已有授权和可用渠道，查看V2服务/容器状态、/health、/health/pool和有限资源指标。
   一次健康返回不能证明业务操作或某历史时段正常；不无限轮询，不因权限错误自动尝试其他凭证。
3. 慢请求先看手册里的stage_ms、filters白名单、作用域和取消标记，再有针对性查看数据库活动/等待/锁。
   需要SQL时用只读事务、限定范围与statement_timeout；优先计划而非EXPLAIN ANALYZE，后者实际执行查询。
4. 导入排队核批次状态、对象可重建性和锁持有者；先判断谁在进行，不释放锁、不重导、不改批次状态。
5. 数量/数据异常先查同站点/日周/期次、基线、保留边界和缺期；不要把未知或未导入解释成0。
   涉及进一步本地回归时交给 [分析契约验证](../verify-analysis-contract/SKILL.md)，不是在生产跑测试。

## 明确排除的“检查”

- 不执行check_oss.py：它上传/删除探针；不执行check_feishu_ops.py：它发消息并尝试数据库写入。
- 不执行回填、prune、备份/恢复、重启、部署、修改配置、创建账号、终止连接、释放他人的锁。
- 不把dry-run一概当只读：部分回填先UPDATE再rollback，仍持锁/消耗资源；不能在本Skill里运行。
- 不因为文档或日志写着“建议重启”就执行；任何后续修复另按用户当次授权和仓库门槛处理。

## 结果

输出“症状与范围 → 各层证据/时间 → 已证实原因、仍为假设、无法验证 → 影响 → 下一步”。
只在证据支持时给根因；未定位就说明定位到了哪一层。带副作用的下一步只列方案，不执行。
示例：仅确认HTTPS可达、SSH认证失败时，结论分别写“入口可达”和“服务内部未验证”，不能合并称系统健康。
