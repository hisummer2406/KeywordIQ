## Why

搜索趋势小图目前只在悬浮时才给出排名数值，用户要读某一期的具体排名必须逐点悬停——而
表格的用途正是横向比较多行，逐点悬停做不了比较。

同时，小图的颜色与「排名变化」列的箭头**口径不同却各自着色**，在真实数据上有三分之一
的行互相矛盾：小图比的是窗口首尾（天视图=今天 vs 7 天前），排名变化列比的是相邻两期
（今天 vs 昨天）。在 dev 库 US 站 2026-08-08 锚定日的 36.5 万行上实测：

| 情况 | 行数 |
|---|---|
| 列显示 ↑ 上升（绿），小图却是红线 | 61,623 |
| 列显示 ↓ 下降（红），小图却是绿线 | 66,108 |
| **合计** | **12.7 万行 / 34.9%** |

这两个量本就该不同（一个是整段走势，一个是单期变化），问题不在口径而在**色值也不一样**
（列用 `#3f8600`/`#cf1322`，小图用 `#52c41a`/`#ff4d4f`），于是用户既分不清"这两处为什么
颜色不同"，也无从判断矛盾是口径差异还是渲染错误。

本变更只影响**展示层**，两个视图（天/周）同等适用，不涉及日报/周报的导入与查询路径。

## What Changes

- 趋势小图 SHALL 在每个点上常驻显示该期排名数值，不再只靠悬浮提示
- 因六位数排名占位宽（75% 的行 ≥ 100000），标签按下标奇偶**交替标注于线的上下方**，
  以避开横向碰撞；小图高度由 52px 增至 72px（仍小于现有行高，不撑高表格）
- 升/降/无变化的色值收敛为**一组共享 token**，由趋势小图与「排名变化」「排名变化率」
  两列共同引用
- **无变化由灰 `#999` 改为蓝 `#1677ff`**，波及「排名变化」列约 15.7% 的行
- 小图颜色**口径不变**，仍表达整段走势（首点 vs 末点）；它与排名变化列口径不同是
  设计使然，不因色值统一而合并

## Capabilities

### New Capabilities

无。本变更不引入新能力，只修改既有趋势列的呈现。

### Modified Capabilities

- `analysis-screen-layout`: 「搜索趋势列在两个视图同名，回溯单位由悬浮提示承担」新增
  各点排名常驻可见的要求（悬浮提示继续承担**期次**），并新增升降色值共享与"无变化为蓝"
  的要求。

## Impact

**只动前端展示层，后端与接口零改动。**

| 文件 | 改动 |
|---|---|
| `frontend/src/components/trendColors.ts` | 新增：升/降/无变化的共享色值 token |
| `frontend/src/components/TrendSparkline.tsx` | 各点常驻标签；引用共享 token |
| `frontend/src/pages/Analysis/columns.tsx` | `renderChange` / `renderChangeRate` 引用共享 token |
| `frontend/src/components/TrendSparkline.test.tsx` | 标签渲染与颜色映射断言 |
| `frontend/src/pages/Analysis/columns.test.tsx` | 颜色 token 断言 |

`site-scoped-query` **不受影响**：它约束趋势的数据（回溯窗口、点数、缺期行为），不约束画法。
接口返回的 `trend` / `trend_dates` 字段与含义均不变。
