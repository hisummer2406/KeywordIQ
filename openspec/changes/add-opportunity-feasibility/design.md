## Context

- 核价单（`pricing_sheet`）按 `owner_id` 私有，他人访问 404；保存版本时服务端重算并存不可变快照（`pricing_sheet_version.result`）；每个市场一条选定方案（`pricing_selection`）。
- 快速核价页支持 `?sheet=<id>` 打开一张草稿，表单按 `draft_input` 回填。
- 机会档案已有「关联自己的 IP 调研、向团队展示摘要」的做法（`add-opportunity-dossier` 决策 6）。

## Goals / Non-Goals

**Goals**：在档案里看到「有没有利润、采购价最多多少」的引擎结论，并能在签决定时留下依据。

**Non-Goals**：在档案里内嵌计算器；大模型调用引擎或生成金额；按 ABA 数据推断售价；接入真实订单做复盘（#171 第二阶段）；改核价单的私有性。

## Decisions

### 决策 1：关联核价单，不复制一份测算

档案只持有关联关系（`pricing_sheet.dossier_id`），不把测算结果抄进档案证据表。核价单本身已有不可变版本、选定方案和「规则已更新」判断；复制一份会出现两个可能不一致的金额来源。代价：核价单被删除时关联随之消失（`ON DELETE SET NULL`），档案的决定里仍保留签署时固化的测算状态（决策 4）。

### 决策 2：摘要只读已保存版本，字段白名单

摘要取核价单的**当前版本**（`current_version_id`）；只有草稿、没保存过版本时显示「尚未保存测算」。每个市场：

- 有选定方案且选定的就是当前版本：取该方案；
- 否则取当前版本里的推荐方案，标「未选定」；没有推荐方案时取第一个可用方案；都没有时只给市场状态与原因。

方案字段白名单：方案名、可用性与原因、求解状态、售价与币种、预计单件利润（人民币）、利润率、投资回报率、保本价、采购价上限、目标差额。**不含**采购成本、费用明细、输入参数——这些是创建人的私有输入。金额原样取自快照字符串，不重新计算、不换算。

团队可见的范围与 IP 调研一致：只有创建人主动挂到档案后，摘要才对团队可见。

### 决策 3：从档案发起核价

`POST /opportunity/dossiers/{id}/pricing-sheets` 以档案标题为产品名、`draft_input = {mode: "target_profit", markets: [档案站点]}` 建一张草稿并关联，返回核价单 id；前端跳到 `/pricing/calculate?sheet=<id>`。端点同时要求 `opportunity:view` 与 `pricing:view`（后者是核价单的既有权限点）。档案详情里的摘要只要求 `opportunity:view`：摘要是档案的一部分，不需要核价权限也能看结论。

### 决策 4：决定固化测算状态

`opp_dossier_decision.pricing_status`（可空 JSONB，迁移前的决定为空）：`state`（`none` / `draft_only` / `calculated`）与每个市场的方案名、选定与否、售价、利润、利润率、结果状态。只是记录，**不阻塞**任何决定——与专利状态的处理一致。

### 决策 5：追问只引用不计算

追问输入加入测算摘要，标明「金额来自定价核算引擎，按费用规则计算」。提示词新增：金额只能原样引用核价结果，不得自行计算、换算或估算；结果状态为未启用或待补资料时说明缺什么。摘要不进入 `cited_evidence_ids`（那是档案证据 id），回答里按核价单名称引用。

## Risks / Trade-offs

- **生产规则未启用**：50 条费用规则仍是草稿、汇率未录，生产上所有市场的结果状态会是「费用规则未启用」。摘要如实显示，不给金额；需要维护人员录入并启用后才有数字。
- **选定方案与当前版本不一致**：选定后又保存了新版本时，选定仍指向旧版本。摘要以当前版本为准，标「选定方案来自旧版本，需重新选定」。
- **团队看到利润数字**：只有创建人主动关联后才可见；采购成本与费用明细不公开。

## Migration Plan

一条迁移：`pricing_sheet.dossier_id`（FK → `opp_dossier.id`，`ON DELETE SET NULL`，部分索引），`opp_dossier_decision.pricing_status`。回滚即删两列。依赖 `4b219decb93a`。
