## Context

现状（`importer._load_facts`）：`is_new = 本期之前 7 天内同站点同周期表里没出现过`，写进事实行。三个问题：只看滚动窗口（掉榜 8 天再回来又是新词）；日报、周报各查各的表；事实表只留 3 个月，窗口外的历史对它不存在。#137 要的「首次入榜」是**永久、日周共享、按站点**的一个事实。

关键观察：`dim_keyword` 以 `(site, keyword)` 唯一、不分区、不参与保留清理、行只增不删——它**本来就是“这个站点见过哪些词”的永久集合**。一个词“不在 `dim_keyword` 里”就等于“从未见过”，不需要再造一张历史表，只需让这张表记住“第一次是哪一期”。

约束：事实表只追加不原地更新（所以首次信息不能写进事实行，补历史时它会变）；`dim_keyword` 约 1500 万行，迁移不能在 alembic 里做长事务全表回填；GIN 索引已很重，不再给 `dim_keyword` 加写放大大的索引。

## Goals / Non-Goals

**Goals:**
- 永久首次记录，独立于保留期；日、周同一份；站点隔离。
- **选哪天，哪天的首次入榜就正确，且与导入顺序无关**：库内最终状态与每期的首次入榜数量只由“导入过哪些报告”决定，换任何导入顺序、重复导入、重试，结果逐位相同。补更早数据只会把首次日期往前修，并让监测起点往前挪。
- 存量不产生“上线日全量首次入榜”；未知如实标为未知。
- 市场分析页的筛选/列/导出/当期数量同一口径。

**Non-Goals:**
- 增长市场与趋势新词识别（#138）。
- #119 里其余事项（数量对照、7 天变化率、类目黑名单等）。
- 回溯重建已被清理的历史——无证据就是 `UNKNOWN`/`EARLIEST_OBSERVED`，不伪造。

## Decisions

### D1：首次记录放在 `dim_keyword`，三列

| 列 | 含义 |
|---|---|
| `first_seen_date date NULL` | 首次出现的报告期次日期（取自文件名日期，与分区归属同源）；`UNKNOWN` 时为 NULL |
| `first_seen_period_type varchar(4) NULL` | `DAY`/`WEEK`：这个日期来自日报还是周报，决定能不能当“某一天” |
| `first_seen_basis varchar(20) NOT NULL` | 这个词条**从哪来**，即首次日期可不可信：`IMPORTED` 词条由导入创建（迁移之后第一次见到这个词，首次日期就是真证据）/ `EARLIEST_OBSERVED` 存量词条，日期只是库内最早能看到的（此前可能还见过）/ `UNKNOWN` 存量词条且无证据 |

`first_seen_basis` **只描述来源，不描述“是不是首次入榜”**。后者是对最终数据的派生（D2）：词条来源可信 **且** 首次日期晚于站点监测起点。这一点是对上一版设计的纠正：上一版把“CONFIRMED / EARLIEST_OBSERVED”在导入时按到达顺序写死，补更早报告后，先到的那批基线词永远是“最早可观测”，与按时间顺序导入的结果不同（PR #141 Codex P1）。

**备选**：新开 `keyword_first_seen` 表——否决，多一次 join 且与 `dim_keyword` 一一对应，没有独立生命周期。**备选**：写进事实行——否决，违反“事实只追加”，补历史时需回写 8 亿行。

时间用 `date` 不用时间戳：业务时间就是报告期次日期，没有时区问题，也不会被上传时间/迁移时间污染。

### D2：什么时候算“首次入榜”（按最终数据派生，与导入顺序无关）

**导入只记录证据，不下“是不是首次”的判断。** 补齐维度时：

- 站点里**不存在**的词 → 新建，`basis=IMPORTED`，首次记录 = 本次 `(report_date, period)`。
- 已存在的词 → 按 D3 只向前修正日期；`basis` 不变（`UNKNOWN → EARLIEST_OBSERVED` 除外）。
- 导入时**不再**读 `min(first_seen_date)` 做“基线期”分流。

**站点监测起点 `B(site) = min(first_seen_date) WHERE first_seen_basis = 'IMPORTED'`**（该站点“导入创建”的行，永久，走 `idx_dim_keyword_first_seen`）。它就是“本系统导入监测到的最早一期”。**只取 `IMPORTED` 行是必须的**：回填只给存量词写 `EARLIEST_OBSERVED` 和更早的日期，若 `B` 取全部行，回填会把 `B` 拉到几个月前，使这些历史日期全部“可判断”，而那些日子里没有任何导入创建的词，于是每天显示 0，把“0”与“无法判断”混淆。回填永远不移动 `B`。

**某期锚定 `on` 的“首次入榜”命中**（映射见 D4）= `basis=IMPORTED` **且** 首次记录落在该期的映射窗口内 **且** `first_seen_date > B`。在 `B` 当天或更早出现的词没有对照期，说“首次”是在没有证据时下判断，所以不算。

**为什么与顺序无关**：`first_seen_date`/`period_type` 是各报告证据按 `(日期, 日优先于周)` 取最小，`min` 可交换可结合；`basis` 由“该词在迁移时是否已存在”决定，与导入顺序无关；`B` 是 `min`。三者都只是“导入过哪些报告”的函数。验证方式不靠推理而靠测试：对同一组报告取全部导入顺序（含重复导入），断言最终 `dim_keyword` 与每期首次入榜数量逐位相同（tasks 3.4）。

**补更早报告会发生什么**：站点先导入 7/12、后补 7/10。7/12 里“7/10 报告里没有”的词，在顺序导入时本来就是 7/12 的首次入榜；乱序时它们在 7/12 导入当下只是 `date == B`（不算），补入 7/10 后 `B` 前移到 7/10，它们自动变成 `date > B`（算）。**不需要重写任何词**，也没有统计要校正。

**新站点首次导入**：全部词 `IMPORTED` 且 `date == B`，当期数量为“不可判断”（不是总词数，也不是 0）。**迁移后的老站点**：存量词是 `UNKNOWN`，之后导入里不在 `dim_keyword` 的词是真新词（`dim_keyword` 从未清理，约 1500 万行，是“见过的词”的完整集合）；`B` 只取 `IMPORTED` 行，回填不会移动它，上线前的历史日期一律“无法判断”，不承诺补出历史首次入榜（库里没有可靠证据）。

判 `B` 只读 `dim_keyword`（永久），**不读 `site_data_stats`**——后者会被保留清理，早期统计行被清掉会让“最早期次”后移。

**一个已知边界**：站点首次引入某个词之后，该词若在保留窗口里被清理、又被重新导入，因 `dim_keyword` 行永不删除，不会被重判。

### D3：已存在的词怎么更新（乱序、补历史、日周交叉）

对本次暂存里**已存在于 `dim_keyword`** 的词，只在证据更早时修正：比较键 `(first_seen_date, rank(type))`，`DAY=0 < WEEK=1`，新键更小才更新：

```sql
UPDATE analysis.dim_keyword k
   SET first_seen_date = :rdate,
       first_seen_period_type = :period,
       first_seen_basis = CASE WHEN k.first_seen_basis = 'UNKNOWN'
                               THEN 'EARLIEST_OBSERVED' ELSE k.first_seen_basis END
  FROM (SELECT DISTINCT keyword FROM _import_staging) s
 WHERE k.site = :site AND k.keyword = s.keyword
   AND (k.first_seen_date IS NULL
        OR (:rdate, :rank) < (k.first_seen_date, rank_of(k.first_seen_period_type)))
```

- **同日并列日优先于周**：日报与周报同一日期时必须有确定结果，否则“周报先导入”与“日报先导入”会得到不同的类型、进而不同的日视图计数。
- **后导入的日报可以细化先导入的周报**：周报 `w` 记 `(w, WEEK)`；之后导入 `d ∈ [w-6, w]` 的日报，`d < w` 则更新为 `(d, DAY)`。周视图两种都落在同一周窗内，计数不变，日视图因此多出精确到日的一条——细化，不是矛盾。
- `UNKNOWN → EARLIEST_OBSERVED`：该词迁移时已存在、没有证据；现在见到它了，所以它“至少在这一期见过”，但它当然不是新词。
- `IMPORTED` 不变；`EARLIEST_OBSERVED` / `UNKNOWN` 不会被升成 `IMPORTED`（存量词的真正首次早于库内证据，永远不能当新词）。重复执行同一期，比较键相等，`UPDATE` 零行（**不写**，与 `dim_product` 的 `IS DISTINCT FROM` 同一条纪律）。
- 事务：与维度补齐同一事务，导入失败整体回滚，不会留下“首次期次=失败的那期”的词。

### D4：日、周映射与当期数量（不存按期统计）

周报期次间隔 7 天（沿用 `importer._PERIOD_CONFIG["WEEK"]` 的 7 天偏移，不新造周定义）。固定映射：**周期 `w` 覆盖 `[w-6, w]`**。命中均要求 `basis=IMPORTED` 且 `first_seen_date > B`。

| 视图 / 锚定期 | “首次入榜”命中 | 可判断条件 |
|---|---|---|
| DAY，日期 `d` | `type=DAY` 且 `first_seen_date = d` | `d > B` |
| WEEK，周期 `w` | (`type=WEEK` 且 `date = w`) 或 (`type=DAY` 且 `date ∈ [w-6, w]`) | `w-6 > B`（整个窗口都在监测起点之后） |

每个词只有一个首次事件，所以 DAY 命中的词在对应 WEEK 视图里**只计一次**（不会“日报事件 + 周报事件”相加）。周报来源的首次**不进任何一天的日视图**——只有周精度，不捏造日期；这使某天的日视图计数可能少于“真实当天新出现”，由界面说明承担。

**不可判断时命中为空**：筛选在不可判断的期次上同样不命中任何词，保证“数量显示无法判断”与“列表筛出来是空的”不矛盾。

例（站点 US）：已导入日报 7/10（最早，`B=7/10`）、7/11，周报 7/18。词 A 在 7/10 日报里；词 E 也只在 7/10 日报里；词 C 首见于 7/11 日报；词 D 首见于周报 `w=7/18`。
- 日视图 7/10 → 不可判断（`d == B`），A、E 都不算。7/11 → {C}。7/12–7/18 任一天 → {}（D 没有具体日）。
- 周视图 `w=7/18`（窗 7/12–7/18，`7/12 > 7/10`）→ {C, D}。`w=7/13`（窗 7/7–7/13，含 `B`）→ 不可判断。
- **之后补导入日报 7/9，含 A 不含 E**：A 变为 `(7/9, DAY)`，`B=7/9`；E 仍是 `(7/10, DAY)` 但现在 `7/10 > B`，**日视图 7/10 → {E}**（可判断了）；C、D 不变。把四份报告按任何顺序导入，结果相同。

**为什么查询时实算，不存按期统计**：命中集合就是 `dim_keyword` 上一段索引范围，大小是单期新词量级（千到万）。按期预存的统计在补历史/乱序时必须校正——不存就没有要校正的东西。`B` 是对 `idx_dim_keyword_first_seen (site, first_seen_date)` 的一次 `min()`，O(1)。

### D5：查询侧用 join 派生，退役 `fact.is_new`

筛选、列、导出、词库盯盘的“是否首次入榜”改为对 `dim_keyword` 的条件（各查询本就 join 它取关键词文本，主键 join 无额外代价），不再读事实行上的 `is_new`。`is_new` 在事实行是**导入时算定**的，补历史后会变陈旧；放在 `dim_keyword` 上才是“当前最准”的一份。

迁移**删除** `fact_daily`/`fact_weekly` 的 `is_new` 列（分区表 `DROP COLUMN` 是元数据操作，随分区继承），并删除 `scripts/backfill_is_new.py`。**备选**：保留列但不再写——否决，留一个口径已经不同、名字还叫“新词”的列，正是 CLAUDE.md 说的“名不副实”。

接口：请求字段 `is_new` → `first_listed`（布尔，两态；`false` 与未传等价）；原按 `is_new` 排序的选项一并去掉（派生自维度表的布尔排序没有使用场景）；响应行字段 `is_new` → `first_listed`（该行当期是否命中上表）+ `first_seen_date`/`first_seen_basis`（供界面标注）。排序白名单里与 `is_new` 相关的项同步改名。`SAVED_MODE_VERSION` +1，旧保存条件静默丢弃；`CACHE_VERSION` +1（会话快照形状变了）。

「排除品牌词」仍是首次入榜筛选下的子条件，只在「只看首次入榜」时随请求发出，语义不变。

### D6：当期数量与统计范围的呈现

**数量走独立接口 `GET /api/analysis/first-listed?site&view&date`**，不塞进 `/scope`：`/scope` 只回可选日期集（与日期无关），而数量是 (站点, 视图, 日期) 的函数，每换日期就要重取。响应 `{judgeable, count, earliest_known_date}`；`count` 用与「仅 `first_listed` 筛选」**同一个计数 base query**（含类目黑名单）算，两处因此不会各说各话。

`earliest_known_date` = 站点监测起点 `B`（`min(first_seen_date)`）。可判断条件见 D4（日 `d > B`；周 `w-6 > B`），不满足时 `judgeable=false`、`count=null`；站点没有任何首次记录（`B` 为 NULL）同样不可判断。界面在作用域栏下方展示，**跟着表格实际加载的切片**（`loadedSite/View/Date`）走，不跟草稿走。

界面三种呈现必须分开：有数量（含真 0）、监测起点（“无法判断首次入榜”）、取数失败（不显示）。**0 与“不可判断”必须分开**，与 CLAUDE.md 里“空表格三种成因”是同一类陷阱。周视图窗口含 `B`（`w-6 <= B`）的那一周只有 `B` 之后几天可判定，计数会偏少，所以整周按“无法判断”处理，不显示偏少的数字。

### D7：存量迁移与回填

- **alembic 迁移**（秒级）：`dim_keyword` 加三列（`first_seen_basis` 默认 `'UNKNOWN'`，常量默认值在 PG15 是元数据操作，不重写表）；建 `idx_dim_keyword_first_seen`；删两张事实表的 `is_new`。**必须手写并用 `--sql` 核对 `PARTITION BY` 未丢**（仓库既有纪律，本变更虽不改分区也要核）。
- **`scripts/backfill_first_seen.py`**（一次性，可重复执行）：按站点、按月分区批处理，从 `fact_daily`/`fact_weekly` 取每个 `keyword_id` 的最早 `(date, type)`，用 D3 同一个比较键写入，`basis` 置 `EARLIEST_OBSERVED`（原为 `UNKNOWN` 时）；`IMPORTED` 的词只向前修日期。**永不写 `IMPORTED`**。输出：按站点的处理数、仍为 `UNKNOWN` 的数、各 basis 计数，并按 `--sample N` 抽样列出（keyword、最早日期、该日事实行是否真存在）供核验。幂等：再跑一遍零更新。
- **上线次序**：迁移 → 部署 → 回填。回填之前导入的新词按 D2 记为 `IMPORTED`，不依赖回填结果；回填只会把更早的证据补进来并让 `B` 前移，已导入词的“是否首次入榜”随之按新的 `B` 重新派生，不需要重写。回填与导入并发时，二者都只往前修且用同一比较键，结果与顺序无关；脚本取咨询锁与导入互斥是否必要，见 Open Questions。

### D8：证据盘点（实施第一步产出）

动手回填前先盘点并写进变更记录：每个站点 × 周期在库内的最早期次、缺期、`import_batch` 里 `COMPLETED` 的最早批次与当前保留下界。**仅有“最早仍保留的一条记录”不等于历史首次**——这就是为什么回填只产出 `EARLIEST_OBSERVED`。

## Risks / Trade-offs

- **周报来源的首次不进日视图** → 日视图某天的数可能偏少。界面说明承担；备选是把周报首次摊到周内某天，会捏造日期，否决。
- **`B` 只取 `IMPORTED` 行的最小首次日期** → 老站点的 `B` 来自迁移后第一次导入的日期，回填不移动它；补导入更早报告才会让 `B` 前移。偏晚只会少算首次入榜，不会把存量误算成新词（存量词 `basis` 非 `IMPORTED`，永不命中）。
- **偏保守的方向是有意的** → 判错时宁可少算首次入榜（`B` 当天及更早、存量词、窗口含 `B` 的周一律不算），不多算；多算会让存量整批涌进当期且无报错。
- **`dim_keyword` 现有 1500 万行，新增 btree 的构建耗时/锁** → `CREATE INDEX` 在迁移里会锁写；`dim_keyword` 只有导入第二段写它，选导入空闲窗口执行，迁移里不用 `CONCURRENTLY`（alembic 事务内不允许），实测耗时记进 tasks。
- **删 `is_new` 不可逆，且迁移早于容器切换** → 部署脚本先迁移、后切换容器，窗口内旧后端仍读写 `is_new`。处理方式待 PR #141 Codex P1 的第二条另行决定（拆成两步迁移 / 其他），不在本次口径修订内。回滚靠 `downgrade` 加回列但值全为默认；因为 7 天口径本来就要废弃，接受。
- **查询多一次 `min()` 子查询** → 对 `idx_dim_keyword_first_seen` 的端点扫描，O(1)，随计数/筛选/列投影各带一份；`EXPLAIN` 实测见 tasks 5.4。
- **词库盯盘共用 `fact_metric_columns`** → 同步改成派生表达式，否则两屏对同一个词显示不同含义（CLAUDE.md 已警示）。

## Migration Plan

1. 迁移（加列/建索引/删 `is_new`；本变更尚未上线，`basis` 取值直接按 `IMPORTED / EARLIEST_OBSERVED / UNKNOWN` 写进同一条迁移，无数据需改）→ 2. 部署后端+前端（同一次发布，前端依赖 `first_listed`）→ 3. 跑 `backfill_first_seen.py --dry-run` 看数量 → 4. 正式回填 → 5. 抽样核验并把数量记入 PR。发布按既有流程，由用户手动触发，不在本变更内发起。回滚：部署回上一版本；迁移 downgrade 加回 `is_new`（全默认）、删三列。

## D8 部署顺序：`is_new` 分两步退役（expand / contract）
