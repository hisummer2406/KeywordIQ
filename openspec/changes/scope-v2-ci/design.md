# 设计

## 决策
- 复用既有路径分类器；公共/未知路径、300 文件截断、API 错误均全量。main 不变。
- push 不能只比较 before：从本仓最近成功且通过门禁的祖先 CI 累计比较；找不到则全量，覆盖此前失败与取消。旧基线只有三项全成功才可信，新基线必须同一运行的范围门禁成功。
- 范围门禁读取 needs 与范围输出，受影响项必须 success，无关项必须 skipped；判定失败不可放行。
- 部署只接受目标 SHA 最新 v2 push ci.yml 运行，分页获取同次 jobs；机器人仅凭 GitHub Actions 同一 check suite 的成功门禁接受 skipped。旧版仍要求三项 success。
- 两仓分别建立提交和 PR，不复制业务提交、不强推 v2。首次策略改动自身触及公共 CI 文件，仍跑全套以建立可信基线。

## 风险与验证
无基线或接口失败可能多跑而非漏跑。单测覆盖范围、基线累计、分叉、截断、失败、取消、缺失与跨运行结果。人工发布入口与生产保持不触发。
