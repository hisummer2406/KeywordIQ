## Why

**分析屏现在展示的是「某一份报表文件里有什么」，而用户要问的是「这段时间里这个词表现如何」。** 选一个日期，看到的就是那一天日报的孤立切片；选一个周，看到的就是那一周周报的孤立切片。两个后果：

1. **掉榜看不见。** 昨天还在榜第 300 名、今天掉出榜单的词，在当天的切片里根本不存在——而「刚刚掉出去」恰恰是选品时最该看见的信号。现在只能靠人肉对比两天的导出文件。
2. **只有一个历史参照点。** 事实表里写死了 `previous_ranking`（上一期），想知道「三天前什么样」「四周前什么样」无从查起，而这正是判断一个词是短期波动还是趋势性下滑的依据。

参照口径来自运营侧长期使用的 ABA 选品表：现排名、历史排名（上期 / 4 期前 / 12 期前）、排名变化、排名变化率、点击前三 ASIN、点击前三品牌。

**为什么是现在**：查询层（`site-scoped-query`）与品牌归位（`keyword-level-brand-category`）都已稳定，此时改行集合语义不与在飞开发冲突；再接入更多查询屏后改动面只会更大。

**影响范围：日报路径与周报路径两者**——两个视图同构地改，只有窗口长度与历史参照点的偏移量不同。

## What Changes

- **视图语义从「报表切片」改为「窗口」**（**BREAKING**，查询语义变更）。视图仍是 `DAY` / `WEEK`，但每个视图有三个互相独立的窗口：

  | | 天视图 | 周视图 |
  |---|---|---|
  | 行窗口（决定哪些词进表） | 锚定日往前 7 天 `[d-6, d]` | 锚定周往前 4 周 `[w-3, w]` |
  | 历史参照点（决定历史排名列） | `d-1` / `d-3` / `d-7` | `w-1` / `w-4` / `w-12` |
  | 趋势窗口（决定小图点数） | 近 7 天 | 近 4 周 |

  历史参照点与趋势窗口**可以超出行窗口**——它们只对已选定的行做补齐，不参与决定行集合。

- **行集合 = 在榜 ∪ 掉榜**。在榜 = 锚定期有数据；掉榜 = 行窗口内出现过但锚定期没有。掉榜行的现排名为空，携带「最后在榜期」与「最后在榜排名」。
- **新增 `fact_dropped` 表**，在导入收尾时算定每一期的掉榜词集合。查询侧只读不算——与事实表「写入时算定、只追加」的既有约束一致。按 `anchor_date` 月度 RANGE 分区，随保留窗口一同 `DROP`。
- **`site_data_stats` 新增 `dropped_count` 列**，让分页总数在无筛选时仍是 O(1)。
- **新增行集合开关 `include`**（`ALL` / `LISTED` / `DROPPED`），默认 `ALL`。它不是筛选条件而是行集合维度。
- **筛选一律以锚定期那一行为准**。必然后果：**任何筛选一生效，掉榜行全部消失**（它们在锚定期没有行可匹配）。因此 `include=DROPPED` 时其余筛选必须在界面上置灰。
- **排序**：默认现排名升序；掉榜行**恒在在榜行之后**，不随升降序翻转，组内按最后在榜排名排。
- **表格列调整**：新增「历史排名」（一列三行）与「排名变化率」；「新词」独立列并入「现排名」列作为标签，与「已掉榜」标签互斥。
- 趋势窗口与行窗口一致（天 7 天、周 4 周）：小图回答的是「这批行所在的这段时间里这个词怎么走」，与行集合同一个区间才对得上。历史参照点可以更远（周最远 12 周前），但那些点只进历史排名列、不进小图。

**不做**（明确排除）：
- **不做月视图**——现有导入链路只认 `DAY` / `WEEK` 两种报表，没有月度数据源。
- **不做搜索量、展示量/点击量、PPC 竞价、SPR、标题密度**——ABA 报表的 21 列里没有这些字段，需要另一条数据源与导入链路，单独立变更。
- 不改导入的三段式主干、不改 OSS 链路、不改错误契约、不改权限模型。
- 不回填历史分区的 `fact_dropped`——数据只留三个月，自然滚动即可全覆盖。

## Capabilities

### New Capabilities
- `window-scoped-rows`: 窗口化行集合——行窗口定义、在榜/掉榜的判定与呈现、`fact_dropped` 的算定与保留、跨两段的分页与计数。

### Modified Capabilities
- `site-scoped-query`: 作用域从「单一事实切片」放宽为「锚定期 + 行窗口」；新增 `include` 请求字段与历史排名补齐；排序规则新增「掉榜恒在末尾」；分页总数改为在榜数 + 掉榜数。
- `analysis-screen-layout`: 结果表列集调整（历史排名、排名变化率、掉榜/新词标签合并），过滤区新增行集合开关及其与其余筛选的互斥规则。
- `multi-site-data-model`: 新增 `fact_dropped` 表与其分区约定；`site_data_stats` 新增 `dropped_count` 列。

## Impact

**数据模型**：新增 `analysis.fact_dropped`（月度 RANGE + 站点 LIST 二级分区）；`analysis.site_data_stats` 加列。两者都需手写 Alembic 迁移（分区表不在 autogenerate 范围内）。`app/table/analysis/partitioning.py` 需为新表创建分区，`retention_service.py` 需把它纳入保留清理。

**导入**：`app/table/upload/import_service.py` 收尾多一步掉榜集合算定（每期一次的反连接：天约 210 万行、周约 1200 万行）。这是本变更唯一的新增运行成本，**必须在真实体量上实测并把数字回填 design.md**。

**查询**：`app/table/analysis/analysis_crud.py` 新增掉榜段查询、历史排名补齐语句、跨两段分页；`analysis_service.py` 编排两段拼接；`search_schemas` 新增 `include` 字段。导出沿用同一份行集合。

**前端**：`frontend/src/pages/Analysis/` 的 `columns.tsx`、`FilterPanel.tsx`、`filters.ts`、`services/analysis.ts`。

**文档**：CLAUDE.md 的「V2 查询层」一节需改写——现有的「任一查询只落在单一事实切片，MUST NOT 突破该边界」不再成立。
