## Why

Refs #154（#148 第二阶段）。第一阶段（PR #149）修好了「新期次统计过期」这个根因，并加了语句超时、完整请求预算和并发闸。仍然留下四类浪费与风险：

- 前端切换条件时，过期请求只在前端被丢弃（`useAnalysisQuery` 的 `requestSeqRef`），后端和数据库照常跑完；客户端断开同样不停止。实测经 SQLAlchemy 的 asyncpg 适配层取消协程，服务端语句不会停（`pg_sleep(8)` 跑满 8 s）。
- 相同条件的查询各自完整执行。除 `competitor_new` 外，查询结果与查询者无关（`user_id` 只喂给该筛选），而导入后大家集中打开最新一期默认页，是最可能重复的形态；但目前没有任何重复率数据。
- 日报「首次入榜 + 排除品牌词」本地冷查询 2.1–2.6 s，离 3 s 预算很近；生产 `dim_keyword` 是本地的 10 倍，是否达标未知。
- 并发闸按 worker 计（4 个 worker 合计 16 个并发），拥堵时轻量接口能否留在预算内没有测量；诊断不区分日报与周报，重采无法分视图统计。

**测量先于优化。** 优化前基线取发布 #149 之后的生产重采（#148 tasks 7.5），尚未发布。本变更先落地不依赖基线、且本身就是正确性改进的部分（取消传播、诊断与测量维度）；去重、缓存、品牌词与计数优化、轻量接口保护的实施与否和深度，由重采与新增的请求指纹统计决定，在 tasks 中设为闸门。

## What Changes

影响**日报与周报两条路径**：所有机制对两种视图一视同仁；闸门判断与验收按日报、周报分别统计。

- **测量维度**：请求摘要带视图与结果键指纹（哈希，不含原始条件），可按日周统计耗时分布，并估算重复率与潜在缓存命中率。
- **取消传播**：前端切换条件时中止过期请求；后端在客户端断开或请求被取消时让数据库侧真正停止执行，且只作用于该请求自己的数据库连接。首选机制是数据库自身检测客户端断开（`client_connection_check_interval`），须先真库验证。
- **请求去重（闸门，2026-11-02 未过，未实现）**：相同结果键的并发请求在同一 worker 内合并为一次执行；不含私有数据的结果可跨用户合并，`competitor_new` 只在同一用户内合并。
- **结果缓存（闸门，2026-11-02 未过，未实现）**：不含私有数据的结果在相同权限范围内共享；键含解析后的期次、规范化条件和全局数据版本；数据版本由数据库触发器在相关表变化时递增，并以 TTL 兜底手工改库。`competitor_new` 不缓存。
- **品牌词排除与精确计数优化（闸门）**：按 `stage_ms` 主导阶段选型，口径不变，有等价性回归。
- **拥堵时保护轻量功能（闸门）**：先压测，不达标再调整；容量调整需有测量依据。
- **诊断提示**：排队超时、超时、统计更新失败的提示按窗口去重、总量有界。
- 各机制均有独立关闭开关，出问题可不发版回退。

不在本变更内：修改业务数据、自动重导或补数据、生产操作与发布、无测量依据地增加连接数或升级硬件、跨 worker 的全局去重或并发上限、引入 Redis 等新组件。

## Capabilities

### New Capabilities

- `analysis-query-coordination`：分析查询的结果键（去重与缓存未过闸门，未写入要求）。

### Modified Capabilities

- `async-request-execution`：新增「客户端断开或请求被取消时数据库侧停止执行」「分析查询拥堵时轻量请求保持在预算内」。
- `request-diagnostics-logging`：新增「分析查询诊断可分视图统计且提示有界去重」。

## Impact

- 代码：`app/table/analysis/analysis_service.py`、`analysis_api.py`、`analysis_crud.py`（品牌词/计数，视闸门）；`database.py`（异步引擎 `server_settings`）；`app/common/request_logging.py`；`config.py`、`.env.example`（新配置同步单位与安全默认值）；`scripts/collect_search_latency.sh`（按视图与指纹统计）；前端 `frontend/src/services/analysis.ts`、`pages/Analysis/useAnalysisQuery.ts`。
- 迁移：`b7d1e4a9c2f3` 品牌命中对与切片就绪标记（design D4）；缓存的数据版本表未过闸门，不建。
- 运维：手工 SQL 改动查询依赖的表会被触发器覆盖；只改事实表而不经导入的手工操作不受触发器覆盖，以 TTL 兜底，并在运维文档注明。
- 不改变导入、导出、竞对与认证契约；列表与导出口径保持一致。
