## ADDED Requirements

### Requirement: 同一用户的相同分析查询并发时合并执行

`POST /api/analysis/search` SHALL 在同一工作进程内，把同一用户、同一作用域、同一规范化条件（含分页与排序）且数据版本相同的并发请求合并为一次数据库执行，结果共享给所有等待者。合并键 MUST 包含用户标识；不同用户 MUST NOT 共享同一次执行。合并 MUST NOT 改变响应内容：与各自独立执行得到的精确总数、行与分页完全一致。

#### Scenario: 相同条件的并发重复请求只执行一次
- **WHEN** 同一用户在同一 worker 内并发发出两个相同的 search 请求
- **THEN** 数据库只执行一次查询序列，两个请求得到相同的响应

#### Scenario: 不同用户不合并
- **WHEN** 两个不同用户发出条件相同的 search 请求
- **THEN** 各自独立执行，互不共享结果

#### Scenario: 条件或数据版本不同不合并
- **WHEN** 两个请求的筛选、分页、排序、作用域或数据版本任一不同
- **THEN** 各自独立执行

### Requirement: 过期或断开的请求在数据库侧停止执行

前端 SHALL 在用户切换条件时中止仍在进行的旧 search 请求，且被中止请求的响应 MUST NOT 覆盖较新的结果。后端在客户端断开或请求被取消时 SHALL 使该请求仍在执行的语句在数据库侧停止，MUST NOT 只放弃等待。停止 MUST 只针对该请求自己的数据库会话，MUST NOT 取消其他用户或其他请求的语句。合并执行中，只有当所有等待者都已离开时才停止底层执行；仍有等待者时 MUST 继续执行。

#### Scenario: 客户端断开后数据库不再执行该查询
- **WHEN** 一个 search 请求的某条语句正在执行时客户端断开
- **THEN** 数据库侧该语句被取消，`pg_stat_activity` 中不残留该请求的执行中语句，连接可继续被复用

#### Scenario: 取消不影响其他用户
- **WHEN** 用户 A 的请求被取消，同时用户 B 的 search 正在执行
- **THEN** 用户 B 的语句不受影响并正常返回

#### Scenario: 连接归还后不会误取消下一个使用者
- **WHEN** 取消到达时该请求已完成并把连接归还给池
- **THEN** 不向该连接发出取消，后续借用该连接的请求不受影响

#### Scenario: 合并执行仍有等待者时不取消
- **WHEN** 合并执行的多个等待者中只有一部分断开
- **THEN** 底层执行继续，剩余等待者得到完整结果

### Requirement: 结果缓存的键与失效保证正确性

分析查询结果缓存 SHALL 为可选能力。启用时缓存键 MUST 包含用户标识、权限范围、规范化条件与数据版本。同一期被重导、统计刷新或保留清理后，旧版本缓存 MUST NOT 再被命中。依赖用户私有数据的结果（如 `competitor_new`）MUST NOT 被不同用户共享。命中缓存与不使用缓存的结果 MUST 完全一致。缓存条目数与存活时间 MUST 有上限，且可通过配置关闭。

#### Scenario: 重导后不返回旧结果
- **WHEN** 某期被重导后用户再次以相同条件查询
- **THEN** 返回的是重导后的数据，而非重导前缓存的结果

#### Scenario: 缓存不跨用户泄露
- **WHEN** 用户 A 的结果已缓存，用户 B 以相同条件查询
- **THEN** B 不会得到 A 的缓存条目，`competitor_new` 结果只按各自的关注数据计算

#### Scenario: 缓存命中与未命中结果一致
- **WHEN** 同一条件分别在缓存命中与关闭缓存时查询
- **THEN** 精确总数、分页边界与行内容一致

#### Scenario: 关闭缓存后行为不变
- **WHEN** 缓存配置为关闭
- **THEN** 所有请求直接执行，除请求去重外无额外行为差异
