# 周视图搜索趋势 设计

## 背景

日视图的走势由 `analysis_crud.trends_stmt` 提供，它把 `FactDaily` 与 `timedelta(days=6)`
写死在函数体里。周视图要有同样的东西，差异只有两处：查哪张事实表、回溯多少天。

## 决策 1：参数化一条语句，而不是日/周各写一条

```python
_TREND_SPEC = {
    "DAY":  (FactDaily,  FactDaily.report_date,       6),
    "WEEK": (FactWeekly, FactWeekly.report_date_week, 42),
}
```

`trends_stmt(site, keyword_ids, on, view)` 从这张表取（事实表, 日期列, 回溯天数）三元组，
其余 SQL 一字不变。

**为什么不各写一条。** 两条并列的语句读起来更直白，代价是同一段回溯逻辑存两份。将来调整
回溯窗口时改一处、忘一处，不会有任何报错——两个视图只是悄悄不一致，而这种不一致要等到
有人同时盯着两个视图看才会被发现。CLAUDE.md 对查询层的要求是"SQL 只有一处定义，作用域
边界、筛选、排序白名单、封顶计数不会漂移"，这里适用同一条理由。`_base_query` 现在按 view
取 `FactDaily`/`FactWeekly` 也是这个路子，本变更与它保持一致。

**为什么用日期范围而不是"最近 7 期"。** "最近 7 期"要按 keyword 分组取前 N，需要窗口函数，
且拿不到分区裁剪——回溯范围不再是一个可下推的日期条件，计划器只能扫更多分区。日期范围
`on - 42天 .. on` 在周报按周导入时正好覆盖 7 期，缺期就少几个点，与日视图"历史不足 7 天
就少几个点"的既有行为同构。

## 决策 2：`trend` / `trend_dates` 提到 `_FactRowBase`

它们此前挂在 `DayRowItem` 上，因为当时只有日视图有。现在两视图共有，放基类。

替代方案是在 `WeekRowItem` 里再声明一遍同名字段——两份声明会各自漂移（描述文案、默认值、
类型注解），而它们本该是同一个东西。现行 spec 那条"两视图 MUST NOT 互相夹带对方独有的
字段"约束的是**独有**字段，趋势已不属此列。

连带结果：`analysis_service.search` 里的 `if view == "DAY"` 分支消失，两个视图走同一段
"先分页、再批量补附加"的代码。

## 决策 3：导出表头按视图分，表格表头不分

表格里「搜索趋势」够用——作用域栏就在同一屏上方，用户知道自己在看日还是周。

CSV 脱离了界面：文件名带了作用域三元组（`US_WEEK_2026-07-18.csv`），但表头若写「近 7 日
趋势」而里面装的是 7 期周报，那是直接写错。故导出按视图取「近 7 日趋势」/「近 7 周趋势」。

## 决策 4：悬浮提示标出周区间

周报期次日期（`report_date_week`）单独显示会被读成"某一天的排名"。

实现复用作用域栏的 `formatScopeDateLabel(date, view)`：日视图渲染 `2026年07月18日`，
周视图渲染 `2026年第27周（06/28–07/04）`。**比原设想的「`2026-07-18 当周`」更好**，
采纳之——它给出真实周区间而不只是一个标签，且格式与日期选择器同源，同一个日期在同
一屏上不会出现两种写法。

这是纯展示层的事，`trend_dates` 传的仍是原始日期，不在后端做文案拼接——后端拼中文会
让这份数据只能给这一个界面用。

> 周序号按周日起算（`06/28` 是周日）。这与被删除的「当周排名变化」曾用过的 ISO 周
> （周一起算）口径不同，但那条链路已不存在，此处纯为展示，不参与任何取数。

## 性能

周视图每页多一次回溯查询：最多 50 个 keyword_id × 7 期，走
`idx_fact_weekly_keyword_history (site, keyword_id, report_date_week)`，与日视图同阶。
42 天的范围条件可能跨 2 个月度分区（日视图的 6 天通常跨 1 个），多扫一个分区在这个量级上
无差别。

## 测试

- 单元：`_TREND_SPEC` 两个视图各自的表与窗口；`shape_trends` 不受影响（按位置取列）。
- 集成：`_seed` 扩成 3 期周报，断言周视图行的 `trend` 是跨期回溯的真实结果（而不是单点），
  且 `trend_dates` 是那 3 个周报日期。**这是本变更唯一能证明"真的回溯了"的证据**——
  只造一期周报的话，单点结果与"根本没查"无法区分。
- 前端：`columns.test.tsx` 断言两个视图都有这一列且标题是「搜索趋势」；
  `TrendSparkline.test.tsx` 断言周视图悬浮文案是整周区间（`2026年第27周（06/28–07/04）`）。
- 导出：日/周两个视图的 CSV 表头各断言一次。

## 不做

- 不改数据模型、不加索引、不动迁移。
- 不做趋势排序（两视图都不允许，与现状一致）。
- 不做可配置的回溯窗口——现在没有第二个取值需求，配置项会先于需求存在。
