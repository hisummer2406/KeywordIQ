## Why

US、GB、DE 三个站点的「热门搜索词」日报和周报，目前都由运营每天从亚马逊卖家后台（品牌分析）手动下载 CSV，再到后台上传。每天约 6 个文件，单个 230MB 到 GB 级。人工环节慢、容易漏期，浏览器直传中途断开时还要人发现后重传（2026-11-10 批次 #200 就是这样）。需要一条无人值守的获取路径，人工上传保留为兜底。

候选数据源有两条，二者**不等价**：

- **SP-API 品牌分析搜索词报表**（`GET_BRAND_ANALYTICS_SEARCH_TERMS_REPORT`）是官方接口，但按公开文档，它只含搜索词、搜索频率排名、点击前三 ASIN 以及点击/转化份额，**不含**现有 CSV 的「点击量前三品牌」「前三类目」和商品标题。
- **用浏览器插件在已登录的卖家后台自动下载同一份 CSV**，数据与人工完全一致，但依赖一台常开、保持登录的电脑和后台页面结构。

本变更先把两条路线和取舍写清楚，设置一个**路线选定闸门**：拿到 SP-API 权限并用真实样本对账后再选定路线，只实现选中的那条。

## What Changes

- 新增「自动获取报表」能力：按站点 × 周期（日、周）每天检查应到期次，缺哪期取哪期，产物进入现有 OSS 直传 → 批次 → `run_import` 管线，不另建导入内核。
- **日报和周报两条路径都受影响**：都由同一调度覆盖，期次日期口径沿用现有 CSV（日报为当天日期，周报为周六结束日）。
- 导入批次新增「来源」字段（人工上传 / 插件自动 / SP-API），导入历史可区分来源。
- 同一站点、周期、期次已有成功或进行中的批次时，自动获取跳过，不重复导入；人工上传仍然可用，规则不变。
- 应到期次超过约定时间仍未成功导入时，通过现有飞书运维机器人告警，提示人工兜底。
- 路线 A（SP-API）另需：LWA 凭证配置、报表的请求-轮询-下载、gzip JSON 流式转换为可导入格式；品牌和类目在这些期次标记为「来源未提供」，不当作 0 或空品牌。
- 路线 B（插件）另需：插件新增定时下载与上传模块，复用现有直传凭证和导入触发接口，后端几乎不改导入逻辑。
- 不改变人工上传、失败重导、保留清理的现有行为。

## Capabilities

### New Capabilities
- `automated-report-fetch`：自动获取热门搜索词报表。覆盖应到期次判定、去重、来源标记、失败与缺期告警、与人工上传的并存规则，以及路线选定闸门。与具体数据源无关的要求写在这里，两条路线都必须满足。

### Modified Capabilities
- `import-history-view`：导入历史需展示批次来源（人工 / 插件 / SP-API）。

（选定路线 A 后，若品牌/类目「来源未提供」需要改变市场分析筛选或统计的可见行为，在实现前另补 `site-scoped-query` 等相关能力的 delta，不在本提案里预先承诺。）

## Impact

- **数据库**：`analysis.import_batch` 新增来源列（Alembic 迁移，默认值覆盖历史批次为人工上传）。
- **后端**：`app/table/upload/`（来源字段、去重判定）、`app/jobs/` 下新增调度 job；路线 A 另加 SP-API 客户端与 JSON 转换模块，可能引入流式 JSON 解析依赖。
- **运维机器人**：`ops_bot` 新增缺期检查与告警。
- **插件**（仅路线 B）：`extension/` 新增卖家后台下载模块与对应 host 权限。
- **配置**：`.env.example` 新增调度开关、期次截止时间；路线 A 另加 LWA 凭证项（只存 ECS `.env`）。
- **外部依赖**：路线 A 需亚马逊批准品牌分析角色，审核结果和周期不受我们控制；路线 B 需要一台常驻运营电脑。
- **关联**：#170（扩展平台接入评估）中 SP-API 条目。
