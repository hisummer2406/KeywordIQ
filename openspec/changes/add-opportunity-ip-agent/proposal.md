## Why

机会中心的「风险待核查」阶段目前只是占位（#76）。#24 已经上线按图检索外观专利，但运营在选品阶段手里通常只有产品名称、卖点和品类，还没有定稿图片；他们需要先用文字把可能撞上的外观专利找出来，再决定是否值得做图、送检。用户已开通智慧芽「专利数据库 MCP」（检索式检索与单件详情，同一把 `ZHIHUIYA_API_KEY`），#180 决定把它接进机会中心，做成「IP 风险专家」Agent。

2026-11-11 用户确认的取舍：

- 做成 IP 专家 Agent：大模型根据产品信息生成检索式，人工确认后才调用 MCP，再由大模型基于证据写风险分析；人工签署意见单独保存。
- 大模型选国内模型，按 OpenAI 兼容协议接入，地址、模型与 Key 由 `.env` 决定（DeepSeek、通义等都兼容）；Key 未到位时 Agent 生成与分析不可用，但人工编写检索式、取证、签署意见仍可用。
- MCP 调用控制：检索式必须人工确认才执行；单次调研最多 20 次 MCP 调用、全站每天最多 200 次，超限拒绝，上限写在 `.env` 可调。

2026-11-11 用户追加：机会中心整体改成对话形式，参考 WorkBuddy 的「工作空间、任务、专家、定时任务」；原来的占位阶段都改成 Agent 专家的形式。用户要求直接开工，下列取舍由实现方决定：

- 页面结构：页内左栏放「新建任务 / 专家 / 定时任务 / 工作空间与任务列表」，主区是任务对话；仍是 `/opportunity` 单页，不加二级路由。
- 一个任务就是一次与专家的对话。目前只有 IP 专家接入，一个 IP 任务对应一条专利调研；信号、选品、验证、商标四位专家以「未接入」名片展示，不发请求。
- 对话里可以追问：大模型只基于本调研已取得的证据回答，不调用 MCP。
- 定时任务：把已成功执行过的检索式设为每周或每月复检，到点自动入队检索；仍受同一套 MCP 预算约束，预算不足或有在途任务时本次跳过并记录原因。

本变更**不涉及**日报或周报路径：不读写 ABA 事实表、分区、物化视图，不参与保留清理，不取导入咨询锁。

## What Changes

- 新增「专利调研」记录：产品名称、产品说明、关键词、洛迦诺分类（可选）、检索法域、销售市场。记录按创建人私有。
- 新增智慧芽 MCP 客户端：固定端点、只开放 `search_patents`、`get_patent_legal_status`、`bibliography`、`abstract_image` 四个工具，`trust_env=False`，错误、未知、无命中分开归类，每次调用留痕且计费状态记为未知。
- 新增 OpenAI 兼容的大模型客户端：只做两步受控生成——「生成检索方案」与「生成风险分析」，输出经服务端结构校验；大模型不直接调用工具，也拿不到任何 Key。
- 所有外部调用都走持久化任务（`SKIP LOCKED` 认领 + 租约，调用期间不持有数据库连接），刷新页面不会重复调用。
- MCP 预算：入队时在咨询锁内核对「本调研已用 + 在途计划」与「今日全站已用 + 在途计划」，超限拒绝并给出数字。
- 证据：每条已执行检索式的总数、返回条数与原始响应；去重后的候选；按需获取的法律状态、著录与摘要附图（附图在取证时下载存库，经鉴权端点读取，因为供应商地址约 1 小时失效）。
- 人工意见：沿用 #24 的风险等级、建议和校验规则（抽成共用函数），按市场追加保存；Agent 分析与人工意见分开，Agent 不给出上架许可。
- 工作空间：按创建人私有的分组，任务可归入或移出；有任务的工作空间不能删除。
- 对话：调研的时间线（检索方案、检索结果、取证、分析、人工意见）按消息流展示；用户追问与 Agent 回答存为对话消息，追问走持久化任务（`ask`）。
- 定时复检：每个调研至多一个定时任务，复检的检索式必须是本调研已成功执行过的；到点由后台轮询入队，复用预算与在途互斥。
- 前端：机会中心改为工作空间布局——左栏导航，主区任务对话（消息流 + 底部输入框），右侧「成果」抽屉放候选、取证与人工意见；专家页以名片展示五位专家，只有 IP 专家可用。

## Capabilities

### New Capabilities
- `opportunity-ip-agent`：专利调研记录、MCP 与大模型的接入边界、受控两步 Agent、人工确认与预算、证据与人工意见、工作台交互。

### Modified Capabilities
- `opportunity-center`：页面从六个阶段 Tab 改为工作空间 + 对话布局（页内左栏，不是路由级二级菜单）；未接入的阶段改为「未接入」专家名片，仍不发请求；允许请求 `/api/opportunity/*` 下的真实端点。

## Impact

- 后端：新增 `app/table/opportunity/`（api、service、task、mcp/llm 客户端、模型、schemas、错误），挂到 `app/api_router.py`；`main.py` 启动独立轮询；`app/table/risk/` 抽出人工意见校验共用函数。
- 数据库：新增 `opp_ip_*` 十张与 `opp_workspace` 一张普通表（含工作空间、对话消息、定时复检），登记 `migration_scope.V2_TABLES`；不新增权限点（沿用 `opportunity:view`，默认仅超管）。
- 配置：`.env.example` 新增 MCP 预算、轮询与超时，以及 `OPPORTUNITY_LLM_*` 四项。
- 前端：`frontend/src/pages/Opportunity/` 重写为工作空间布局，IP 专家组件改为对话卡片；新增 `services/opportunityIp.ts`。
- 外部费用：MCP 与大模型调用都可能计费；只有显式动作触发，计费状态无回执时记为未知。
