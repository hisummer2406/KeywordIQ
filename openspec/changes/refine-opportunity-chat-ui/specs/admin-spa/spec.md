## MODIFIED Requirements

### Requirement: 对话类界面的组件与安全边界

SPA 的对话类界面（机会中心的专家任务对话、机会档案的追问）SHALL 使用与 antd 主版本匹配的 Ant Design X 作为气泡、输入框与会话列表组件，
`@ant-design/x` 的主版本 SHALL 满足 antd 6 的 peer 要求。

对话输入框的提交动作 MUST 只触发「向大模型追问」。任何会调用付费外部服务（如专利检索、取证）的动作 MUST NOT 由对话输入框的提交或回车直接触发，
SHALL 继续经过显示调用次数的确认后才入队。

两处对话 SHALL 使用同一套消息规范：用户输入、AI 回答与任务事件（检索、取证、签署、失败等）在视觉上可区分；模型名与时间作为弱化的元信息展示，
MUST NOT 混入消息标题。专家任务对话 SHALL 根据任务进度突出一个主要动作，其余动作 SHALL 可在同一界面找到；动作不可用时 SHALL 说明原因。
折叠的过程记录 SHALL 在摘要中保留失败与未知的数量，失败与未知的任务 MUST NOT 被折叠隐藏。

对话中大模型的**回答**（专家任务对话的 Agent 回答、档案追问的回答）SHALL 以受限 Markdown 渲染：只允许段落、标题、列表、粗体、斜体、删除线、
行内代码、代码块、引用、表格与分隔线。回答里的原始 HTML MUST 作为字面文本显示，MUST NOT 被解析为元素；链接 MUST 只显示其文字，图片 MUST 只显示其替代文字，
MUST NOT 产生可点击的链接或发起图片请求。渲染器 MUST NOT 使用把字符串当 HTML 注入的方式（如 `dangerouslySetInnerHTML`）。
其他大模型文本（检索方案、风险分析）与外部供应商返回的文本 MUST 继续作为纯文本渲染。

#### Scenario: 回车只发送追问

- **WHEN** 用户在专家任务对话的输入框里输入问题并按 Enter
- **THEN** 只创建一次追问任务，不产生检索或取证任务，也不消耗检索预算

#### Scenario: 输入法组合态下回车不提交

- **WHEN** 用户用中文输入法在输入框里选词，按 Enter 确认候选
- **THEN** 不提交，也不丢失已输入内容

#### Scenario: 回答含 HTML 或脚本

- **WHEN** 大模型回答里包含 `<script>`、`<img onerror=…>` 等 HTML
- **THEN** 页面按字面文本显示这些标记，不产生对应的 DOM 元素

#### Scenario: 回答含链接或图片语法

- **WHEN** 大模型回答里包含 Markdown 链接 `[文字](javascript:…)` 或图片 `![替代文字](https://…)`
- **THEN** 只显示「文字」与「替代文字」，页面里没有 `<a>` 或 `<img>`，也不请求该地址

#### Scenario: 回答含标题、列表与表格

- **WHEN** 大模型回答使用 Markdown 标题、有序或无序列表、表格
- **THEN** 按对应的标题、列表与表格排版显示；表格过宽时在回答内部横向滚动，不撑出页面横向滚动条

#### Scenario: 检索方案与分析仍为纯文本

- **WHEN** 检索方案的理由或风险分析的摘要里包含 Markdown 语法
- **THEN** 按字面文本显示，不渲染成标题、列表或链接

#### Scenario: 按进度突出主要动作

- **WHEN** 专家任务已有成功的检索但还没有风险分析，且大模型已配置
- **THEN** 输入区的主要动作是「生成风险分析」，生成检索方案、手写检索式、签署人工意见等其余动作在「更多」菜单里可找到

#### Scenario: 检索记录折叠但失败可见

- **WHEN** 一次执行检索中有检索式失败
- **THEN** 折叠的检索记录摘要显示失败的条数，展开后可看到每条检索式的结果

#### Scenario: 对话输入忙时不可提交

- **WHEN** 任务有在途的排队或执行中的工作
- **THEN** 追问输入框不可提交，且界面说明原因（等当前任务完成），不发出请求
