# 设计

## 背景

IP 专家任务对话（`IpAgent/Conversation.tsx` + `MessageItems.tsx`）用 Ant Design X 的 `Bubble.List`、`Sender`；档案追问（`Dossier/AskPanel.tsx`）只用了 X 的 `Prompts`、`Sender`，消息仍是自写卡片。两处的模型文本都按 `admin-spa`「对话类界面的组件与安全边界」以纯文本渲染（归档变更 adopt-antdx-opportunity-ui 决策 D8）。

## 目标 / 非目标

目标：两处对话看起来是同一套东西；用户一眼分清自己问的、AI 答的和系统做了什么；输入区只突出当前该做的一件事；回答能显示标题、列表、表格而不扩大注入面。

非目标：不改后端与接口；不合并两条业务流程；不更换组件库或升级依赖；不给检索方案、风险分析、专利著录渲染 Markdown。

## 决策

### D1：共用的对话表现层放在 `pages/Opportunity/chat/`

- `roles.tsx`：`Bubble.List`/`Bubble` 的三种角色配置——`user`（右侧、`filled`、浅主色背景、最大宽度 80%）、`ai`（左侧、`borderless`、专家头像、正文占满）、`event`（左侧、`borderless`、无头像、缩进对齐 AI 正文、字号 13）。另有 `MetaLine`（模型名、时间、操作人，12 号三级文字色）与 `CitationTags`（「引用：」+ 标签）。
- `AnswerMarkdown.tsx`：受限 Markdown（见 D2）。
- 两处对话都从这里取样式，各自保留自己的数据和动作。档案追问不用 `Bubble.List`：它嵌在档案详情的长页面里，`Bubble.List` 自带滚动容器会形成页中页；直接按顺序渲染 `Bubble`。

### D2：受限 Markdown 用 react-markdown，不用 x-markdown

候选：

| 方案 | 注入面 | 代价 |
|---|---|---|
| `react-markdown` + `remark-gfm` | 直接生成 React 元素，不解析 HTML（不接 `rehype-raw`） | 两个新依赖 |
| `@ant-design/x-markdown` | 基于 `marked` 生成 HTML 字符串再转换，需要依赖净化器兜底 | 新依赖，安全边界落在净化配置上 |
| 自写子集解析 | 最小 | 表格、嵌套列表等边界情况自维护 |

用户 2026-11-13 选定第一项。约束：

1. **在语法树上降级**：自带一个 remark 小插件，在 mdast 上把 `html` 节点改成 `text`（`<script>`、`<img onerror>` 原样显示为文字，与原纯文本时一致，用户能看到模型到底输出了什么，而不是悄悄消失），把 `link`/`linkReference` 换成其子节点（只留文字），把 `image`/`imageReference` 换成替代文字。`react-markdown` 本身也不会解析 HTML。
2. **元素白名单兜底**：`allowedElements` 只放 `p h1–h6 ul ol li strong em del code pre blockquote table thead tbody tr th td hr br`，`unwrapDisallowed`；`a`、`img` 不在其中。`urlTransform` 一律返回空串。插件漏掉的情况由这两道拦住。
3. **版式**：标题统一压到 15/14px，不超过气泡正文的层级；表格包在 `overflow-x: auto` 容器里，代码块 `pre` 自身横向滚动，避免撑破气泡和窄窗口横向溢出。
4. **范围**：只用于 IP 专家 Agent 回答与档案追问回答。用户自己输入的追问仍按纯文本（`pre-wrap`），检索方案、风险分析、专利著录与供应商文本不变。
5. 版本钉死 `react-markdown@10.1.0`、`remark-gfm@4.0.1`（均发布超过半年，满足 `minimumReleaseAge`）。

### D3：IP 对话按阶段给一个主要动作

`nextAction(data)` 纯函数，按顺序取第一个成立的：

| 条件 | 主要动作 |
|---|---|
| 还没有成功检索，没有方案，大模型已配置 | 生成检索方案 |
| 还没有成功检索，没有方案，大模型未配置 | 手写检索式 |
| 还没有成功检索，已有方案 | 确认检索式（用最新方案打开待确认卡） |
| 已有成功检索，没有分析，大模型已配置 | 生成风险分析 |
| 还有市场未签署人工意见 | 签署人工意见 |
| 都完成 | 无（只留追问输入框） |

主要动作是输入框上方的一个主按钮，有调用说明的放进它的 Tooltip。其余动作（重新生成方案、手写检索式、生成/重新生成分析、签署人工意见、定时复检、移动到工作空间、任务记录）进「更多」下拉；不可用时菜单项禁用并在文字里写明原因（大模型未配置、先成功执行至少一条检索、等当前任务完成）。检索与取证本身仍只能在卡片里经过调用次数确认才入队，主按钮最多打开待确认卡，不会直接入队。

顶栏：第一行任务名（省略号 + 悬浮全文）、右侧「成果 · 候选 N」与「更多」；第二行弱化元信息：`IP 专家 · 工作空间 · MCP 预算 a/b · 全站今天 c/d`，已设定时复检时追加其状态。大模型/智慧芽未配置的提示条不动。

输入区：去掉常驻的「只调用大模型…」一行，并入占位符；忙时的占位符与禁用不变。

### D4：消息到角色的映射

| 时间线条目 | 角色 | 说明 |
|---|---|---|
| 任务简报、用户追问 | user | 简报内容较长，仍在右侧 |
| 检索方案、风险分析、Agent 回答、待确认检索式、在途任务 | ai | 方案/分析/待确认卡占满宽度 |
| 执行检索、取证、人工签署、失败/未知任务、定时复检跳过 | event | 一行图标 + 摘要 + 状态标签 + 链接式动作 |

检索事件默认折叠：摘要写「执行检索 N 条 · 成功 x · 失败 y · 新增候选 z」，失败/未知数为红/橙色；展开显示原有逐条结果。失败与未知任务仍用 `Alert`，不折叠。标题中原来的「检索方案 · 模型名」改为标题「检索方案」，模型名和时间移到底部 `MetaLine`。

### D5：档案追问的形态

每条记录拆成一问（user 气泡，底部操作人与时间）一答（ai 气泡）：排队/执行中显示加载；完成显示受限 Markdown 回答，底部 `CitationTags` + 模型名；失败/未知显示原有文字与「可以再问一次」。顶部说明与建议问题（`Prompts`）保留。

## 风险 / 取舍

- **新依赖带来的供应链面**：两项均为 unified 生态的主流包，版本钉死；后续升级按常规依赖评估。
- **Markdown 渲染与纯文本的差异**：CommonMark 会把段内单个换行显示成空格，而模型常用单换行分行。不加 `remark-breaks` 依赖，改为段落、列表项、引用与单元格用 `white-space: pre-line`——文本节点里的换行原样显示，与原纯文本观感一致。
- **主要动作推断可能与用户意图不符**：所有动作都还在「更多」里，推断错了只是多点一下，不会误触发计费。
- **视觉效果只能实屏确认**：单元测试只覆盖结构、安全与动作可达；改前/改后截图与键盘、对比度检查由用户在浏览器完成。
