## Context

- `add-opportunity-ip-agent`（PR #184 已合并 v2，未部署、未归档）提供了工作空间、专利调研任务、对话与受控的大模型调用。它的表全部以 `opp_ip_research` 为根，按创建人私有。
- 排名趋势详情（`app/table/keyword/trend_service.py`）已有单关键词的五态期次口径；市场分析的行投影（`analysis_crud.fact_metric_columns`）是点击前三商品的唯一定义。
- 生产数据（2026-11-12 只读核查）：US/DE/GB 日报 58 期、周报 9 期；关键词约 640 万；没有搜索量、销量、Amazon 售价、BSR、评论。
- 没有租户；机会中心此前仅超管可见。

## Goals / Non-Goals

**Goals**

- 一个真实关键词或产品想法能走完：建档 → ABA 证据 → 补人工证据 / 挂 IP 调研 → 追问 → 签署决定与复查日期 → 到期复查看变化。
- 每一条证据有来源、期次与署名；缺失、未接入与真 0 分开。
- 运营可用，团队可见。

**Non-Goals**

- Signal 收件箱、机会评分、多专家编排、审批流、租户隔离。
- 大模型自由调用工具；自动补齐第三方数据。
- 改 IP 调研的私有性与既有接口；改 ABA 事实表。
- 定价核算的自动关联（先用人工证据承接成本与售价）。

## Decisions

### 决策 1：档案是新实体，不复用工作空间表

`opp_workspace` 是按创建人私有的任务分组（同一用户下名称唯一），语义与「团队可见的研究对象」不同。把档案字段加到工作空间上，会让私有分组与团队档案共用一张表、两套可见性。新建 `opp_dossier`；工作空间保持原样，继续组织个人的专家任务。IP 调研通过新增的可空列 `opp_ip_research.dossier_id`（`ON DELETE SET NULL`）挂到档案。

### 决策 2：团队可见、可写，全部署名

持有 `opportunity:view` 的用户都能读写任意档案；每条关键词、证据、决定、消息都记录操作人。档案有创建人与负责人，「接手」把负责人改成自己。不做逐档案的成员管理：现阶段是一个团队，细分权限会先于需求出现。档案不提供删除，只能归档（`archived_at`），避免已签署的决定失去出处。

### 决策 3：ABA 证据是确定性快照，只追加

快照在请求内同步计算（全部是异步数据库查询，不阻塞事件循环），存为一行 `opp_dossier_evidence(kind='aba_snapshot')` 的 JSONB。每个词：

- 日榜与周榜的五态期次：直接调用 `trend_service.get_keyword_trend(range_='ALL')`，不重写口径；
- 在榜期数 / 已导入期数、最佳与最新在榜排名；
- 7 天前对比：取最新在榜期 `d` 与 `d-7` 当天的排名；`d-7` 不在榜则为空，不找邻近日期代替；
- 首次入榜三项证据（同上一个调用返回）；
- 最新在榜期的点击前三商品、品牌、份额：用 `fact_metric_columns` 与 `join_fact_row_dims` 投影；
- 近 30 天（日榜）点击第一商品的更换次数与逐期点击前三 ASIN：按 `(site, keyword_id, report_date)` 索引读取。

跨词：在各词最新在榜期的点击前三里出现两次及以上的 ASIN 列为共同商品。

不在 `dim_keyword` 里的词记为「保留期内未进入过该站点 ABA 榜单」，不是 0。单个档案最多 20 个词：快照的查询量与词数成正比（每词约 6 条索引查询）。

快照带 `anchor_day` / `anchor_week`（计算时该站点已导入的最新期）。同一档案在两个锚定期都没变时再次刷新，直接返回已有快照，不追加重复行。

不合成机会分，也不输出「值得做 / 不值得做」。快照只给可复算的事实和一组确定性的提示（如「在榜不足 7 期，不判断趋势」）。

### 决策 4：缺口是固定清单，人工证据挂在类别上

缺口类别是代码常量：搜索量、销量、售价、BSR、评论、供应成本、商标、其他。前七类在界面恒显示「未接入」；有人工证据时显示条数，但不改变「未接入」的事实。人工证据必填：类别、内容、来源名称、观测日期；可选来源链接。只能作废（记录作废人与时间），不能编辑或删除。

外观专利不在缺口清单里：它由 IP 调研承接（决策 6）。

### 决策 5：决定只追加，规则在服务端

`opp_dossier_decision`：`verdict`（advance / need_evidence / watch / reject）、`reason`（必填）、`next_step`、`recheck_date`、签署人、`snapshot_id`（签署时最新的 ABA 快照，可空）、`ip_status`（签署时关联调研的人工意见摘要）。

- need_evidence 与 watch 必须有不早于今天的复查日期；
- 档案既没有 ABA 快照也没有有效人工证据时，不能签 advance；
- 专利未核查不阻塞 advance（历史文档里这是待决项；本期由实现方定为不阻塞），但签署记录里写明当时的状态，界面在签署前提示。

档案状态由最新一条决定推出：无决定为 researching，其余为对应 verdict。状态冗余存一份在 `opp_dossier`（`status`、`recheck_date`），与决定在同一事务里写，供列表筛选。

### 决策 6：IP 调研只挂自己的，档案展示摘要

关联、解除关联都要求调研属于当前用户（沿用调研的私有性，取不到 404）。档案详情对所有人展示关联调研的摘要：产品名、创建人、候选数、最近任务状态、各市场最新人工意见的风险等级与建议。明细（检索式、候选、附图、对话）仍只有创建人能打开。这是对「调研按创建人私有」的一处有意放宽，范围仅限摘要字段，且仅当创建人主动挂到团队档案时发生。

### 决策 7：追问复用受控单步生成，独立的小队列

`opp_dossier_message` 一行同时是用户问题与它的回答：`question`、`status`（queued / running / completed / failed / unknown）、`answer`、`cited_evidence_ids`、`model`、`usage`、租约。不复用 `opp_ip_task`：它的每一行都必须属于一条专利调研，预算、互斥与调用留痕也都按调研计。

- 入队：同一档案同时只有一个在途问题（部分唯一索引）；大模型未配置返回 422。
- 执行：IP 轮询器里追加一轮，`FOR UPDATE SKIP LOCKED` 认领并写租约，调用期间不持有会话，收尾在新事务。租约过期转 unknown，不自动重发。
- 输入由服务端组装：档案信息、最新 ABA 快照的精简版、有效人工证据、决定、IP 摘要、最近 6 轮问答。证据段明确标记为数据。要求 JSON `{answer, cited_evidence_ids}`；回答截断到 2000 字，不属于本档案的证据 id 丢弃。
- 系统提示：只根据给定证据回答；证据没有的数据说明「档案里没有」，不得估算销量、搜索量、利润或给出机会评分；不替人做决定。

### 决策 8：权限

`OPPORTUNITY_VIEW` 移出 `SUPER_ONLY_PERMISSIONS`，授予 admin、operator、analyst；新迁移为已有库补 `role_permission`。`SUPER_ONLY_PERMISSIONS` 保留为空集合及其机制，以后的试用功能还能用。全部档案端点挂 `opportunity:view`。

机会中心此前仅超管可见，IP 专家的端点因此只挂了 `opportunity:view`。授予运营后，这等于让运营绕过「`risk:search` 只默认给 admin、检索按次计费不随角色铺开」的既有约定（`permissions.py`，#24）。所以 IP 专家里会向智慧芽计费的三个动作（执行检索、取证、设置定时复检）另外挂 `risk:search`；只调用大模型的动作（生成方案、分析、追问）与不产生外部调用的动作不加。超管不受影响（`is_super` 放行全部权限点）。

### 决策 9：页面

仍是 `/opportunity` 单页、URL 查询参数承载视图。左栏新增「机会档案」作为第一项与默认视图；`view=dossiers`、`dossier=<id>`、`view=new-dossier`。专家、定时任务、工作空间与任务保持不变。

档案详情自上而下：标题区（站点、状态、负责人、复查日期、刷新证据）→ 自上次决定以来的变化 → 关键词与 ABA 证据 → 缺口与人工证据 → 专利风险 → 决定记录与签署 → 追问。

## Risks / Trade-offs

- **团队可写没有细分权限**：误操作靠署名与只追加追溯；档案不可删除。
- **快照同步计算**：20 个词约 120 条索引查询；导入刚完成、缓存未热时可能偏慢。先实测，必要时再改为任务。
- **IP 摘要的私有性放宽**：仅摘要、仅主动关联时；在规格中写明。
- **运营获得 IP 专家入口**：计费动作另由 `risk:search` 把守（决策 8），运营默认只能建调研、生成方案与追问；MCP 预算与全站每日上限不变。
- **追问质量取决于国内模型**：输出不合格记为失败可重试；提示词禁止估算缺失数据。

## Migration Plan

一条迁移（`4b219decb93a`）：建五张表、给 `opp_ip_research` 加 `dossier_id`、授予 `opportunity:view`。不动事实表。回滚即撤销授权、删列、删表。
