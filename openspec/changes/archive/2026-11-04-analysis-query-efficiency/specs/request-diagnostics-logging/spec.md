## ADDED Requirements

### Requirement: 分析查询诊断可分视图统计且提示有界去重

`POST /api/analysis/search` 的请求摘要 SHALL 带视图（日报/周报）与结果键指纹，使耗时分布可按视图分别统计，重复率与潜在缓存命中率可从日志估算。结果键指纹 MUST 为不可逆哈希，MUST NOT 含原始筛选内容或用户标识以外的私有数据。排队超时、语句或请求超时这类预期内的保护性拒绝 SHALL 记 WARNING 且不打调用栈，并按类型与请求路径在时间窗内去重：窗口内只记首条，其余计数，下一次记录时报出上个窗口省略的次数；日志总量 MUST 有界，MUST NOT 因拥堵而放大日志量。每个请求的结局仍由请求摘要逐条记录。真正的外部故障（如第三方服务不可用）MUST NOT 被去重或去掉调用栈。查询统计更新失败已按批次的重试次数上限有界，不另行去重。诊断与错误响应 MUST NOT 泄漏 SQL 与内部细节。

#### Scenario: 可按视图统计耗时
- **WHEN** 统计一段时间内的分析查询耗时
- **THEN** 可以按日报与周报分别得到分布

#### Scenario: 可估算重复率
- **WHEN** 按结果键指纹与时间窗汇总请求摘要
- **THEN** 可以得到并发重复与短时间内重复查询的比例

#### Scenario: 拥堵时同类提示被去重
- **WHEN** 短时间内大量请求触发同一类排队超时
- **THEN** 该类提示每个窗口只记一条且不带调用栈，下一次记录时报出省略次数，不逐条刷屏

#### Scenario: 外部故障不被去重
- **WHEN** 第三方服务不可用导致 503
- **THEN** 每次都带调用栈记录，不受去重影响
