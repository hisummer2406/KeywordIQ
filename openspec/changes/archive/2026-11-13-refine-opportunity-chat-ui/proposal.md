# 机会中心对话界面：统一消息样式、精简操作、受限 Markdown

## Why

用户反馈机会中心的对话不好看、不好读（#7）。代码层面确认三类问题：

- IP 专家任务对话与档案追问是两套样式：前者全部用描边气泡，后者把每轮问答塞进带边框的自写卡片。
- IP 对话的顶栏同时铺开任务名、专家、工作空间、MCP 预算、全站用量、定时复检、成果入口；输入区常驻四个动作按钮加一行调用说明，不论任务处在哪一步。
- 回答只能按纯文本显示，模型给出的标题、列表、表格以 `#`、`|` 原样出现；标题里混着模型名与时间；检索、取证等过程记录和回答用同样的气泡，层级不清。

`admin-spa` 现行要求模型文本一律纯文本，并规定「如需渲染 Markdown，SHALL 另行变更并单独评估注入面」。本变更就是这次单独评估。

## What Changes

- **统一对话规范**（两处共用 `pages/Opportunity/chat/`）：用户输入为右侧浅色填充气泡；AI 回答为左侧无边框正文、带专家头像；任务事件（检索、取证、签署、失败、跳过）为紧凑的事件行，与对话区分。模型名与时间降为气泡底部的弱化元信息；引用统一为底部标签行。
- **档案追问**改用同一套气泡（问在右、答在左），不再是自写卡片；业务流程与接口不变。
- **IP 对话按阶段只突出一个主要动作**（生成检索方案 → 确认检索式 → 生成风险分析 → 签署人工意见），其余动作收进「更多」菜单，禁用时写明原因；顶栏收成任务名 + 一行弱化元信息（专家、工作空间、预算），定时复检、移动工作空间进入「更多」。
- **过程记录折叠**：检索记录默认显示一行摘要（条数、成功/失败、新增候选），展开看每条检索式；失败数在摘要上始终可见；失败与未知任务仍以醒目提示显示。
- **对话回答渲染受限 Markdown**：仅 IP 专家的 Agent 回答与档案追问的回答。用 `react-markdown` + `remark-gfm`，只允许段落、标题、列表、粗体/斜体/删除线、行内代码与代码块、引用、表格、分隔线；原始 HTML 一律作为字面文本显示，链接只显示文字、图片只显示替代文字，不产生 `<a>`、`<img>`。其他模型与供应商文本（检索方案、风险分析、专利著录）仍按纯文本。
- **依赖**：新增 `react-markdown@10.1.0`、`remark-gfm@4.0.1`（用户 2026-11-13 选定）。不升级、不更换现有依赖。

## Capabilities

### Modified Capabilities

- `admin-spa`：「对话类界面的组件与安全边界」——把「一律纯文本」改为「对话回答走受限 Markdown，其余仍纯文本」，写明允许的元素、HTML/链接/图片的处理，以及消息角色区分与主要动作的展示要求。

## Impact

- 前端：`pages/Opportunity/IpAgent/{Conversation,MessageItems}.tsx`、`pages/Opportunity/Dossier/AskPanel.tsx`，新增 `pages/Opportunity/chat/`；对应测试。
- 依赖：`frontend/package.json`、`pnpm-lock.yaml` 增加两项。
- 不改后端、接口、权限与业务语义；计费确认、预算校验、任务互斥、幂等令牌、人工签署、证据引用与既有错误状态原样保留。
