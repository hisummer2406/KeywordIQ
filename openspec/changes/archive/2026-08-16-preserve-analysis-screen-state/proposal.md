## Why

从 ABA 数据选品屏切到别的一级菜单再切回来，用户填好的作用域与过滤条件**全部回到默认值**，
同时 4 个接口被重新请求一遍。两个症状同一个根因：umi 4.6 没有 keepalive，路由一变
`AnalysisPage` 真的被卸载，切回来是全新实例，`useEffect(..., [])` 的挂载副作用无条件重跑。

实测本地 dev、热缓存、US 日视图、无筛选，每切回一次的代价：

```
GET  /api/upload/sites        19ms
GET  /api/analysis/scope      28ms
GET  /api/analysis/categories 13ms
POST /api/analysis/search    132ms
```

用户并没有要求刷新数据，这部分负载是纯浪费；而在 2 vCPU 的 RDS 上，约 200 并发用户
反复切页产生的量不可忽略。更要紧的是**丢的是用户的活儿**：一屏精心填好的筛选条件，
切走一次就没了。详见 issue #31。

本变更**只影响查询路径的前端**，与日报 / 周报的导入路径无关；日视图与周视图同等适用。

## What Changes

- 分析查询屏的界面状态（作用域、草稿与生效两份条件、排序、分页、结果行与总数、
  日期与类目清单）**提到组件之外**，由一份会话内缓存持有。
- 挂载时先看缓存：**有缓存则原样复原并跳过全部初始化请求**；没有（首次进入或刷新过
  页面）才走现行的首屏初始化。
- ProTable 的 `request` 增加一条短路：请求参数与缓存中那次完全相同时**返回缓存、不发请求**。
- 切回时**一并恢复滚动位置**，落在结果行渲染完成之后。
- 缓存**在登出时清空**——同一标签页内换人登录不得看到上一个用户的结果。
- 「查询显式触发」的既有语义不变：要新数据仍然只有「立即查询」一个入口。
- **首屏不再自动查数据表**（原先是「拉完作用域立即查一次」）。仍拉站点、作用域与类目
  ——它们是选择器渲染的前提——但表格留空，等用户点「立即查询」。进屏时的默认条件多半
  不是用户想看的那组，而数据表查询是这一屏最贵的一次请求。
- 随之要求**空表格区分「还没查」与「查出来是 0 行」**：前者给出「点立即查询」的提示且
  不显示条数，后者显示「搜索结果：0」。两者都是空表格，含义相反。

**不改**：查询接口、查询语义、草稿态与生效态分离的架构。范围限定在
`frontend/src/pages/Analysis/`，工具箱的「持续增长市场」屏有同样毛病但不在本次范围内。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `analysis-screen-layout`: 新增一条要求——离开查询屏再返回时，界面状态与结果 SHALL
  原样保留且 MUST NOT 触发任何数据请求。这是屏级交互契约的一部分（与「查询显式触发」
  同类），故落在这份 spec 而非 `site-scoped-query`（后者约束的是查询语义，不变）。

## Impact

- **代码**：`frontend/src/pages/Analysis/index.tsx`（状态改由缓存承载、挂载副作用加闸、
  `request` 加短路分支）；新增一处缓存模块与其纯函数判定逻辑；`src/app.tsx` 的登出流程
  增加一次清空。
- **依赖**：不新增。`plugin-model` 已启用，不引入 `react-activation` 等 KeepAlive 方案。
- **接口 / 数据库 / 配置**：无改动，`.env.example` 无需同步。
- **后端负载**：切页产生的 4 个请求降为 0（首次进入与刷新页面不变）。
- **已知不覆盖**：缓存是会话内的，刷新页面即清空；工具箱屏的同类问题另开变更。
