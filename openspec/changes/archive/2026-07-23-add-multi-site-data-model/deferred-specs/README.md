# 已推迟的规格（不属于本变更的产物）

这两份规格是在本变更还包含导入与查询链路时写成的，共约 300 行场景，是多轮讨论沉淀的结果。
本变更收窄为**只做数据模型**后，它们不再属于本变更的交付范围，因此移出 `specs/`（`specs/**/*.md`
是 OpenSpec 的产物路径，留在里面会让本变更承诺它并不交付的行为）。

它们各自的归属：

| 文件 | 归属变更 |
|---|---|
| `site-scoped-import/spec.md` | V2 变更 2：导入链路重写 |
| `site-scoped-query/spec.md` | V2 变更 3：查询链路重写 |

创建那两个变更时（`/opsx:propose`），直接取用这里的内容作为其 specs 起点。

**注意**：这些内容写于 V1 尚未确定退役之前，其中若干处以"维持现状"为由保留了 V1 的行为
（例如查询规格中关于可见性的表述）。V2 是重建、不背历史包袱，取用时需要按当时的产品决策重新校对。

已知需要复核的点：
- 周报独有关键词的可见性——已确认为"日视图不可见、周视图全量可见"，规格中的相关措辞需去掉"维持现有行为"的框架
- 排序字段白名单——需与最终的双视图列定义对齐
- 7 天走势基于所选日期回溯（而非最新日期），这条是后加的，需确认已完整落入场景
