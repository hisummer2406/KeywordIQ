# 设计

## D1 主入口与附录

CLAUDE.md 保留跨域规则、关键静默失败判据和按改动范围的必读表；7 个领域附录保留细则与证据。
OpenSpec specs 仍负责业务要求与场景，领域指南是维护约定附录，不能新增另一套业务规格。
Markdown 链接按文件相对路径，代码/命令路径相对根目录；不复制已有 skill/command 的执行流程。

## D2 压缩与去向

迁出不等于删除约束。旧文按连续段逐项登记审计去向，领域内原文原则上保留；配置复制改为引用
.env.example/config.py，原容量估算标记为历史并停止作为当前容量保证。主文件合并重复核心判据。
不通过去空行、拼长行达标，同时记录字符数、最大行长和领域指南行数。

## D3 授权与范围

本次用户已明确批准压缩方案，允许执行保留/压缩/迁移与已核实纠错；其他未经确认的规则删除不执行。
首轮逐段核对是文档去向审计；没有重新验证每项线上环境、旧真机记录或业务实现，不冒充全量实现审计。
AGENTS 的 Code Review Rules 保持原样；仅入口声明按需读取，避免顶层要求与领域分层冲突。
OpenSpec context 中的旧 RDS/400 连接/V1 参数改为引用入口，不引入新的配置副本。

## D4 验证与交付

核对主文件行数/字符数、全部原段落去向、领域迁移原文差异、Markdown 链接/代码路径、Git ignore、
AGENTS 审核段一致性、OpenSpec 严格校验与 git diff --check。
纯文档按仓库约定不跑业务全量；已有 conventions 用例可 focused 验证文档默认值一致性，不新增测试或工具。
保留独立 worktree 和原主工作区；本次不擅自发布/合并/关闭 Issue。
