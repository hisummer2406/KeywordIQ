# 设计：插件令牌改为从网页会话同步

## 决策 1：新增独立的「网页地址」，不复用 API 地址

看起来可以省掉一个配置项——生产环境 nginx 同时托管 SPA 与 `/api`，两者本就同域。但
**本地开发不是**：网页在 `:8001`（umi dev server），API 在 `:8000`（uvicorn），是两个来源。

复用 API 地址的后果不是报错，而是**去 `:8000` 读 localStorage，读到空**——那个来源下从来
没有网页写过令牌。表现与"用户没登录"完全一样，而真正的原因是配置项被复用了。开发环境
恰恰是最需要这条路能走通的地方（真机验收都在这里做）。

未填时回退到 API 地址：对生产环境即正确，对开发环境会给出"没有该来源的标签页"这个可辨的
失败，而不是静默读空。

## 决策 2：注入读取而不是 `externally_connectable`

另一条路是让**网页主动把令牌推给插件**（manifest 声明 `externally_connectable`，网页调
`chrome.runtime.sendMessage(extensionId, ...)`）。它更"正统"，但要求：

- 前端代码里**硬编码扩展 ID**——而未打包的开发版扩展每次重新加载都可能换 ID
- 因此必然要再加一个"扩展 ID"配置项，配置负担反而更重
- 且需要改前端代码，本变更的边界是只改插件

注入读取（`chrome.scripting.executeScript`）不需要网页做任何配合，代价是需要 `scripting`
权限与目标来源的 host permission——后者本来就要申请。

## 决策 3：三种失败必须分开说

`syncTokenFromWeb` 的结局是四选一，**不能合并成"同步失败"**，因为三种失败对应的动作完全
不同：

| 结局 | 含义 | 运营该做什么 |
|---|---|---|
| `ok` | 取到令牌 | —— |
| `no_permission` | 用户拒绝了该来源的权限 | 重新点按钮并允许 |
| `no_tab` | 没有该来源的标签页 | 打开 KeywordIQ 网页 |
| `no_token` | 有标签页但 localStorage 没有令牌 | **在网页上登录** |

合并之后，"没开网页"和"开了但没登录"会给出同一句话，而运营在这两种情况下要做的事不一样。
这与既有的四种目录状态、三种空表格成因是同一条纪律。

## 决策 4：401 后自动重试**至多一次**，重发同一份请求体

`background.handleCapture` 收到 `auth_error` 时同步一次令牌，拿到**不同的**令牌才重试，
且只重试一次。三个约束：

- **必须是"不同的令牌"才重试。** 否则网页那边也过期时，会用同一个坏令牌再打一次，
  纯属浪费一次请求。
- **重发的必须是同一份请求体**，尤其是 `request_id` 与 `captured_at`——它们已由 content
  script 冻结（`add-competitor-browser-collector` 决策 3）。服务端按幂等键回放，
  所以重试**不会**产生第二条观测记录。若在这里重新生成幂等键，一次真实观测就会被记成两次。
- **至多一次。** 401 的成因除了"过期"还有"令牌本身无效"，后者重试多少次都一样。

## 决策 5：保留手动粘贴，作为折叠的兜底入口

自动同步依赖 `chrome.scripting`、依赖目标来源的标签页、依赖用户授权——真机上任何一环
都可能失败。把手动入口整个拆掉，等于让插件在那种时候完全不可用，而这条路径此前是被验证
过能用的。

代价是设置页多一块内容。放在折叠区里，默认不展开：**默认路径只有一条**（点按钮同步），
兜底路径需要主动展开才看得见。

## 决策 6：不动 `getAuthToken()` 的签名

决策 1 当初把耦合点收在这一个函数上，正是为了今天。`background.ts` 仍然调
`getAuthToken()`，只是在拿不到时多走一步同步。DOM 解析、请求组装、幂等键、错误分类
一行不动。

## 决策 7：只加 `scripting`，**不加 `tabs`**

`chrome.tabs.query({ url })` 看起来需要 `tabs` 权限，实际上**持有被查询来源的 host
permission 就够**——而那个权限本来就要申请（不申请连 `executeScript` 都做不了）。

不加的理由不是洁癖：`tabs` 授予的是**读取所有标签页的 URL 与标题**，安装时 Chrome 会
显示"读取您的浏览记录"这类警告。为一个已经能靠 host permission 达成的能力去换这条警告，
是纯亏。

下一个人如果看到 `tabs.query` 就"顺手补上" `tabs`，请先确认它真的失败了——失败的表现是
查询返回空数组（而不是抛错），与"确实没有那个标签页"难以区分，所以更要先确认再加。

## 明确不做

- **不解决 24 小时过期**。令牌仍是网页 JWT。自动同步把"每天手动粘一次"降到"每天可能
  多一次静默同步"，但令牌生命周期没变。
- **不做权限收窄**。插件拿到的仍是全权限令牌。要限权限必须后端签发另一种令牌。
- **不做单独吊销**。要收回插件权限，目前仍只能改该用户的密码或禁用账号。

这三条合起来才是"正式方案"，它们都需要后端新增可吊销、可限权限的长效令牌。本变更**有意**
不碰后端，因此这三条原样留着——写在这里是为了下一个人不必重新推导一遍为什么它们还在。
