## Why

项目负责人于 2026-09-20 明确决定：**不做数据库备份**。而现行 spec 仍要求自建 PostgreSQL 有自动化异地备份、ops-bot 每日自动备份并做「备份超期」告警。这份差异带来两个后果：

- ops-bot 已据此移除每日定时备份与「备份逾期」巡检（PR #113、#114），代码与 spec 不一致；
- Codex 复审（PR #113，P1）据 spec 判定该改动违规、建议恢复备份。以后任何按 spec 审查的人都会得到同样的结论。

让 spec 如实反映这个决定，并把「数据保护由主机与磁盘本身承担、无自动备份」作为**明示的已接受风险**记下来，而不是让它以「缺一项功能」的形态存在。

## What Changes

- `ops-backup`：移除「定时与手动备份」「备份新鲜度与保留期检查」「避免与既有调度重复」，新增「仅手动触发备份」与「手动备份的保留期清理」；保留失败准确报告、产物核对与查询、隔离环境恢复验证。
- `ops-monitoring-alerting`：状态查询、定时巡检、每日摘要三处不再包含备份新鲜度/备份情况。
- `containerized-deployment`：移除「自建 PostgreSQL 有可运行的备份」，改为明示「不提供自动化备份」及其后果。

**BREAKING（对 spec 的读者）**：原「RDS 自动备份消失后的等价替代」这一等价性不再成立——主机或数据盘丢失后数据不可恢复。这是有意接受的取舍，不是遗漏。

## Capabilities

### New Capabilities

- 无。

### Modified Capabilities

- `ops-backup`：定时备份、备份新鲜度告警、与既有调度去重三项要求被移除或改写。
- `ops-monitoring-alerting`：状态查询、巡检项、每日摘要不再含备份。
- `containerized-deployment`：自动化备份要求改为明示不提供。

## Impact

- 仅 spec 文档；代码已在 PR #113、#114 中对齐，不含运行时改动。
- 保留的能力：飞书 `备份` / `备份记录` 手动指令与 `scripts/backup_selfhosted_pg.py`。
- 若日后重新需要自动备份，应新开变更恢复相应要求，而不是回滚本变更。
