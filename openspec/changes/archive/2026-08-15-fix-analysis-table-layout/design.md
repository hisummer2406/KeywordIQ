## Context

分析查询屏上线后实机使用暴露的四处问题，全部在展示层。其中一处（历史排名间距）是上一个
变更 `trend-point-labels-and-color-tokens` 引入的，另一处（图片覆盖率）是既有设计的代价
被低估、而非缺陷。

## Goals / Non-Goals

**Goals**

- 日期选择器在两个视图下都合适
- 消除两处不必要的空白（历史排名列内、商品列与品牌列之间）
- 让取不到图的卡牌仍有出路

**Non-Goals**

- **不引入真实图片地址来源**（抓商品页 / PA-API）。与既有决定相悖，且工量与合规都需单独
  讨论。本变更只承认覆盖率低这个事实并给出补偿
- 不改后端、不改接口、不改任何查询语义

## Decisions

### 决策一：日期选择器用内容自适应，而非按视图给两个定值

按视图切换宽度（天 150px / 周 280px）也能解决，但它把「文案有多长」这件事复制成了第二份
真相：日期格式化在 `scopeDateLabel.ts`，宽度却写在 less 里，改格式必须记得同步改宽度，
而漏改不会报错、只会又一次截断。让宽度跟着内容走就没有第二份真相。

配套 `popupMatchSelectWidth={false}`：触发器变窄后，下拉若仍与触发器同宽，选项就会被
截断——而用户正是在那个列表里挑日期。两者必须一起改，只改前者会把问题从触发器搬到下拉。

### 决策二：定宽给内容固定的列，富余留给要读内容的列

`点击前三 ASIN` 的内容是 3×92 + 2×8 = 292px 的固定结构，给它 300px（留 8px 余量）。
富余空间由「关键词」列吸收——它是 `ellipsis: true` 的读内容列，宽度增加会真实增加可读
长度；而卡牌列宽度增加只产生空白。

这推翻了 `columns.tsx` 里"不给 width：让它吃掉所有剩余横向空间"那句注释，需连注释一并
改掉并写明理由，否则下一个人会照着注释再改回去。

### 决策三：历史排名改为两段定宽，整体左靠

原实现 `flex: 1` + `textAlign: right` 让数字撑满并贴右边缘。改为标签定宽（按最长的
「12 周前」取 52px）、数字定宽（按六位数 `433,961` 取 52px）右对齐，容器不再拉伸。

数字之间的个位对齐由**共用同一个定宽盒子**保证，与原来靠列边缘对齐等效——上一个变更引入
的那条回归测试（三个数字占同一宽度）因此仍然成立，不需要放宽。

### 决策四：整张卡牌可点击，而不只是有图时

链接挂在卡牌而非图片上：无图时占位方块同样可点击，而那恰恰是最需要它的时候。地址取
`amazonProductUrl(asin, domain)`，与 `amazonSearchUrl` 并列、复用同一个域名来源
（`site_registry` 经接口下发），并沿用它"拿不到域名就返回 null、由调用方降级"的约定——
宁可不给链接，也不要拼出 `https://undefined/dp/...`。

域名来自**生效作用域**而非草稿，与关键词链接一致：用户切了站点但没点查询时，表格里还是
上一个站点的数据，链接必须跟着数据走。

## Risks / Trade-offs

**自适应宽度会让作用域栏在切换视图时轻微跳动**。可接受：跳动一次，换来的是两个视图下都
不截断；固定宽度则是每次使用都别扭。

**卡牌可点击后，用户可能误以为图缺失是可修的**。spec 里已把覆盖率实测数据写进要求正文，
供后来者查证。
