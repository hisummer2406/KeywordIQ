# analysis-query-coordination Specification

## Purpose
定义分析查询的结果键：哪些条件进键、何时区分用户，作为重复率统计以及将来请求合并或结果缓存的唯一依据。
## Requirements
### Requirement: 分析查询结果键区分可共享与私有结果

分析查询 SHALL 为每个请求计算结果键，其指纹写入请求摘要，作为统计重复请求、判断是否需要请求合并或结果缓存的依据（2026-11-02 实测两者都未达闸门，未实现；以后实现时也 MUST 以它为唯一键）。结果键 MUST 包含站点、视图、规范化后的筛选、分页与排序条件，以及决定可见性的权限范围。请求含依赖查询者私有数据的筛选时，结果键 MUST 额外包含用户标识；其余请求的结果与查询者无关，结果键 MUST NOT 包含用户标识。此类私有筛选 MUST 在结果键模块中登记，当前登记表为空（原有的 `competitor_new` 已按 `site-scoped-query`「已下架的竞对新发现参数明确拒绝」退役）。语义相同而字段顺序或默认值写法不同的请求 SHALL 得到相同的结果键。

#### Scenario: 当前所有请求跨用户共享结果键
- **WHEN** 两个具备相同权限范围的用户以相同条件查询
- **THEN** 两者的结果键相同，且不包含用户标识

#### Scenario: 已退役参数取假值不改变结果键
- **WHEN** 一个请求带 `competitor_new=false`，另一个请求条件相同但不带该字段
- **THEN** 两者的结果键相同

#### Scenario: 语义相同的请求键相同
- **WHEN** 两个请求只在字段顺序或显式写出默认值上不同
- **THEN** 两者的结果键相同
