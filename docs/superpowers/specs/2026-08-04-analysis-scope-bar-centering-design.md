# ABA 数据选品作用域栏居中与站点标识设计

## 背景

ABA 数据选品页面第一行是作用域栏，包含站点、视图、日期、搜索框、立即查询按钮和条件修改提示。当前控件从容器左侧开始排列，用户希望这一行作为整体水平居中，并希望站点使用“国旗 + 国家站名称 + 代码”的统一文案。

本次变更作为 KeywordIQ 端到端 CodingAgent 流程的首个小型试点，用于验证从需求确认、代码定位、最小实现到测试和构建验证的完整闭环。

## 目标

- 将作用域栏中的全部控件作为一个整体水平居中。
- 将站点选项和选中值展示为 `国旗 国家站（代码）`，例如 `🇺🇸 美国站（US）`。
- 保留现有控件顺序、宽度、间距和交互行为。
- 窗口宽度不足时继续允许自动换行，换行后的内容保持居中。
- 不改变查询参数、状态管理、接口调用和其他页面区域布局。

## 非目标

- 不调整站点、视图、日期等控件自身的文字对齐方式。
- 不拆分或重新排列作用域栏控件。
- 不改变搜索框、按钮、提示标签的视觉规格。
- 不修改后端接口或数据模型。
- 不在前端维护逐站点国旗映射，也不新增图片资源。
- 不重构页面整体布局。

## 现状

`frontend/src/pages/Analysis/ScopeBar.tsx` 使用 Ant Design `Space` 作为作用域栏根容器：

```tsx
<Space size="middle" wrap style={{ width: '100%' }}>
```

容器占满卡片宽度，但未指定主轴对齐方式，因此控件默认左对齐。

## 方案比较

### 方案一：在现有 Space 上增加居中样式

为根 `Space` 增加 `justifyContent: 'center'`。这是推荐方案，因为它不引入新结构，也不改变现有 `wrap` 行为。

### 方案二：增加外层 Flex 容器

外层 Flex 可以提供更多布局控制，但会为单一居中需求增加无必要的 DOM 层级。

### 方案三：改用 Row 和 Col

栅格适合需要固定列宽和断点策略的复杂布局。本次没有重新分栏需求，采用栅格会扩大变更范围并提高回归风险。

## 最终设计

采用方案一，将作用域栏根容器调整为：

```tsx
<Space
  size="middle"
  wrap
  style={{
    width: '100%',
    justifyContent: 'center',
  }}
>
```

站点、视图、日期、搜索框、立即查询按钮和条件修改提示仍然属于同一个 `Space`，因此它们在空间足够时作为一组居中；空间不足时按现有规则换行，每一行由 Flex 布局居中。

## 站点标识设计

站点接口继续返回现有 `SiteOption`：

```ts
interface SiteOption {
  code: string;
  name_zh: string;
  domain: string;
}
```

前端通过两个纯函数生成展示文案：

```ts
siteCodeToFlag('US'); // 🇺🇸
formatSiteLabel({ code: 'US', name_zh: '美国', domain: 'amazon.com' });
// 🇺🇸 美国站（US）
```

`siteCodeToFlag` 将两位 ISO 3166-1 alpha-2 大写代码转换为 Unicode Regional Indicator Symbol。项目已登记的 `US`、`GB`、`DE` 都满足该条件。函数先去除首尾空格并转成大写；非两位英文字母返回空字符串，避免产生无意义字符。

`formatSiteLabel` 使用接口返回的 `name_zh` 和规范化代码，格式固定为：

```text
{国旗} {name_zh}站（{CODE}）
```

项目当前三个站点最终展示为：

- `🇺🇸 美国站（US）`
- `🇬🇧 英国站（GB）`
- `🇩🇪 德国站（DE）`

站点 `Select` 的 `value` 仍然是原始站点码，只有 `label` 改变。因此站点切换、接口请求、作用域解析和数据隔离逻辑不变。下拉选项与选中值复用同一个 label，不产生两套展示规则。

## 数据与交互

本次没有数据流变化：

1. `ScopeBar` 仍然接收相同 props。
2. 站点、视图、日期及搜索条件仍由父组件控制。
3. 所有 `onChange`、回车查询和按钮查询行为保持不变。
4. `dirty` 提示的显示条件保持不变。
5. 站点选择值仍为 `US`、`GB`、`DE`，只改变可见文案。

## 异常与响应式行为

- 容器宽度不足时保留 `wrap`，不强制单行，也不引入横向滚动。
- 条件修改提示出现或消失时，整组控件会按当前实际宽度重新居中，这是预期行为。
- 本次不新增自定义断点；沿用 Ant Design `Space` 的换行行为。

## 验证方案

### 自动化验证

- 增加或更新 `ScopeBar` 相关测试，验证根容器应用水平居中样式。
- 增加纯函数测试，覆盖 `US`、`GB`、`DE` 国旗转换和非法代码回退。
- 增加组件展示测试，验证站点下拉使用 `🇺🇸 美国站（US）` 格式。
- 运行 ABA 数据选品页面相关前端测试。
- 运行前端构建，验证类型检查和生产构建没有回归。

### 视觉验证

- 宽屏下确认整行控件作为一个整体水平居中。
- 窄屏下确认控件正常换行、无横向滚动，并保持居中。
- 触发条件修改提示，确认提示出现后整体仍然居中。
- 确认站点下拉选项和选中值均使用国旗站点文案。

## 完成标准

- 三个现有站点分别展示为 `🇺🇸 美国站（US）`、`🇬🇧 英国站（GB）`、`🇩🇪 德国站（DE）`。
- 页面查询、筛选和状态提示行为与变更前一致。
- 相关测试及前端构建通过。
- 实际页面在宽屏、窄屏和提示显示状态下通过视觉检查。
