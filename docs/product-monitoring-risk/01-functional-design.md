# KeywordIQ 产品库、产品监测与风险核查设计

日期：2026-09-05。状态：供讨论的功能方案，未进入实现或采购。

## 1. 建议定位

围绕同一份产品档案，连通“收集产品、观察变化、风险取证、人工审核、持续复核”。运营发现一个产品后，不必在收藏夹、监控工具、侵权表和聊天记录之间反复复制链接。

三个业务对象必须分开：

- **产品档案**：我们正在研究或准备销售的具体产品，以及它的市场、素材版本、关联竞品和负责人。
- **风险案例**：过去发生过什么投诉、平台处置或审核发现，依据是什么，适用范围是什么。
- **审核单**：谁针对哪个产品版本、哪些市场、哪些风险类型做过检查，给出了什么建议。

产品库负责保存研究对象，监测负责发现变化，风险核查负责组织证据和审核。机会中心引用这些对象，负责决定是否值得继续投入，避免两边各建一套推进状态。

建议新增一级“产品库”，放在“竞对监控”之后、“风险核查”之前。理由是它承载跨来源的产品档案与人工资料，已有数据域不能完整容纳。此项是菜单变更提案，不是现行约定。

| 页面 | 页内组织 | 用户的主要操作 |
|---|---|---|
| 产品库 | 全部产品 / 我关注的 / 需要处理；顶部标签和筛选 | 新建、批量加入、查看档案、开启监测、发起核查 |
| 产品详情 | 总览 / 市场证据 / 监测记录 / 风险审核 / 附件与历史 | 看当前状态和依据，补资料，发起机会研究 |
| 竞对监控 | 保留 Amazon 卖家、独立站及现有新发现流 | 从发现流把某个商品加入产品库；不自动把整店商品全部加入 |
| 风险核查 | 审核工作台 / 外观专利 / 商标查询 / 风险案例 | 领审、补证、查权利、登记结论、维护历史案例 |

不为这些 Tab 增加固定侧栏。批量工作使用宽表；图片案例检索支持卡片；完整审核使用独立详情页，避免把多图比对挤进窄抽屉。

产品列表首屏保留：产品图片与名称、来源/市场、负责人、研究状态、监测状态、分市场风险摘要、最后更新、操作。价格、BSR 等作为可选列；缺数据不显示 0。

## 5. 产品库

### 5.1 入库与身份

入口包括 ABA 结果前三商品、竞对新发现、独立站商品、ASIN/链接粘贴、人工图片与资料。收藏只需对象和来源，不能强迫用户填完所有审核资料；发起正式审核时再补市场、版本和待审内容。

产品分两层：

- **来源商品**：Amazon 用站点＋ASIN；独立站优先用域名＋稳定商品 ID；无法解析的链接保留为待确认对象。
- **研究产品档案**：内部独立 ID，可关联多个来源商品、拟售版本和参考竞品；允许没有 ASIN。

跨站点同 ASIN、同一父体的不同子体、不同网站的相似图片不能自动当成同一个可复用审核结论的对象。同款识别先产出“建议关联”，人工确认后关联，不删除来源身份。

ABA 的 `dim_product` 仍服务既有分析模型。拟售产品、私有附件、标题版本和市场属性不写回该共享维度表。

### 5.2 档案内容

| 信息块 | 字段 |
|---|---|
| 基础资料 | 中文名称、标题、关键词、类目、图片、来源链接、关联商品、创建人与负责人 |
| 拟售版本 | 外观与结构说明、品牌、包装、标题、五点、素材附件、版本号 |
| 市场范围 | 明确销售站点；审核涉及的法域另存；新增市场需要追加审核 |
| 研究记录 | 来源关键词、ABA 站点/日周视图/期次、选中原因、关联机会档案 |
| 监测 | 已选指标、来源、频率、最近成功时间、采集状态、变化事件 |
| 风险 | 各市场的审核状态、重要证据、当前结论版本、复核原因 |
| 商业判断 | 成本测算引用、观察笔记、保留/归档原因；机会的推进与否决仍由机会中心负责 |

标签用于分类，不承担工作流。删除标签不删除档案或监测。档案归档后保留审核历史，停止其主动监测订阅；恢复时先展示数据过期状态。

## 6. 产品监测

### 6.1 先区分三种监测

1. **产品经营变化**：价格、标题、图片、BSR、评分数等。
2. **市场需求变化**：关联关键词在 ABA 中的排名与份额变化。
3. **风险依据变化**：出现内部新案例、命中规则变更、正式权利记录状态变化或拟售版本变化。

收藏不等于开启付费采集。用户选择监测内容后，界面展示可用来源、实际频率、预计消耗和失败状态。浏览器被动采集显示“随浏览更新”，不得写成每天自动更新。

### 6.2 现有需求如何落地

| 原需求 | 建议表达和可用条件 |
|---|---|
| FAV-01：上架 3 天内 | Amazon 改成“近 72 小时新发现”，沿用既有卖家基线口径；已证实的真实上架时间单独展示 |
| FAV-02：5 天内且有排名 | “近 120 小时新发现，且有目标大类 BSR”；当前没有 BSR 数据时提示未接入，不拿 ABA 搜索词排名替代 |
| FAV-03：库存变动 | 必须有同卖家、同变体、同市场与配送条件的可比较观测；库存变化不换算订单量 |
| FAV-04：周/月大类排名上升 | 同站点、同类目节点、同来源、同周期口径才能比较；类目切换或任一端缺数据时不生成上升信号 |
| FAV-05：连续日单量 >5 | 需要日粒度销量及其性质；只有月估算值时不可实现，也不可除以 30 冒充日单量。连续 3 天仅为待确认默认值 |
| FAV-06：单量激增 | 完整的相邻两个 7 天窗口才比较；基期为 0 时显示“从零出现”，不生成无穷增长率；“>100%”是待确认阈值 |
| FAV-07：已出单 | 真实订单、第三方估算和购买提示分开命名；现阶段不能统一包装为“真实已出单” |

已实现 Amazon 发现流复用现有逻辑，不另立第二套基线。Shopify 的发布时间、首次发现时间继续分别保留；目录完整性条件不满足时不判下架。

### 6.3 事件与提醒

事件卡包括对象、前后值、两个观测时间、来源、触发规则和版本、当前处理状态。用户可标记已读、暂缓、加入机会或发起复核。

业务变化和数据异常分流：抓取失败、授权到期或缺期进入“数据异常”，不伪装成价格归零、下架或风险解除。

同一批观测重试不重复生成事件；规则按“对象＋市场＋事件类型＋规则版本＋来源观测”去重。连续命中合并更新，只有新增证据、级别变化或用户设定的复核到期才再次提示。

一期使用站内待办；钉钉消息作为后续通知渠道，需单独完成授权与收件范围配置。普通变化可汇总，审核阻塞实时进入待办。

## 7. 风险核查与审核单

### 7.1 检查什么

文字商标、外观设计是 RISK-01 必做范围。同时给历史资料留出版权、发明/实用新型、受限产品与其他风险类型。首期不声称自动查完这些扩展类型，但允许人工登记证据与阻塞事项。

三个维度分别记录：

- **权利或政策类型**：商标、外观、版权、发明/实用新型、受限商品等，可多选。
- **事件类型**：投诉、律师函、诉讼、平台预警、内部审核发现。
- **处理结果**：移除 Listing、账号停用、库存冻结、申诉、撤诉等。

“律师函”不是一种知识产权，“冻结”也不是侵权类型。历史案例中的应对措施只作为过去处理记录，不自动推荐为当前合规做法。

### 7.2 审核粒度与流程

审核单绑定：**产品版本＋目标市场集合＋检查范围＋本轮检索证据**。一单可检查多个市场，每个市场有独立结果。GB、DE、US 是销售站点；注册局、法域及地域效力单独记录，不能从页面语言推断。

流程为：草稿 → 待审核 → 审核中 → 待补证或待复审 → 已出具结论。发生关键变化后标记需复核并新建审核轮次，旧结论保持可读。

将三种状态分开：

| 维度 | 示例 |
|---|---|
| 检索执行状态 | 未检索、检索中、成功无命中、成功有候选、覆盖不足、来源失败 |
| 人工风险判断 | 待核实、存在风险、暂未发现相关风险、无法判断 |
| 业务决定 | 继续验证、补证、条件通过、不建议上架 |

无命中只能生成“本次范围内未检索到”，不能自动生成“可以上架”。产品被修改后，旧结论可以显示，但必须带“仅适用于版本 vN”。

### 7.3 审核页面

- 页首：产品、版本、目标市场、负责人、审核人、待办截止日期。
- 主区左侧：拟售图片、包装、标题与五点；可切换视角并查看原始素材。
- 主区右侧：专利/商标候选、内部案例、官方链接和查询快照；支持与产品图并排放大。
- 页尾：按市场填写结论、依据、未覆盖范围、整改条件、附件和复核日期。

选择“不相关候选”时记录理由；选择“条件通过”时必须列条件和需复核的材料。审核人负责风险意见，有权业务负责人决定是否推进；两者都留身份与时间，不能用“运营”列猜测审核签名。

### 7.4 外观专利

输入支持商品链接/ASIN取图、上传多视角图片、关键词或权利号检索。无法取图时直接补图，不制造抓取成功的占位结果。

结果列：候选图片、名称、权利号、法域、申请/公开日期、来源状态、权利人、相关度、来源详情。用 LOC 辅助缩小结果，但错误分类不能悄悄排除其他可能候选。

证据保留查询图、裁剪图与原图关系、参数、执行时间、覆盖范围、结果分页范围、来源版本。相似度只服务排序；没有检查过的结果不能被记录成“全部排除”。

### 7.5 商标与文字检测

输入品牌名称、所有人、注册号，或者粘贴拟售标题/五点/包装文字。OCR 结果先让用户核对；纯图形商标的相似检索作为独立能力开关，未接入时明确提示。

结果至少显示：商标、申请人、法域/注册局、尼斯分类、具体商品与服务描述、状态及其更新时间、申请/注册号、官方或来源详情。

匹配层级：权利号/ASIN/确认的品牌精确匹配 → 词组与别名匹配 → 模糊文字与图像候选。保留命中位置与原因，品牌词出现也可能是兼容性描述，不能直接判违规。

关键词分析页仅增加轻量风险提示和证据入口，不逐行实时调用外部接口。关键词命中与前三商品命中分别显示，避免用户不知道风险指向词还是商品。

### 7.6 持续复核

以下变化影响结论适用性：拟售外观、包装、品牌或 Listing 文字变更；增加市场；授权证明到期；审核人设定的复核时间到期；来源提供的新权利状态或相关案例。

规则更新先产生“需要复核”的候选，不自动推翻人工结论。第三方权利状态监测只有在接口支持增量或可承担轮询成本时启用；未接入时保留人工复核提醒。

## 8. 内部风险案例库

案例详情包括原名称与标题、原图片、标准化风险类型、投诉/处置经过、涉及市场、品牌词和权利号、证据附件、处理记录、来源、登记人、校对人及有效性状态。

内部限制规则单独维护：词/商品对象、适用市场、限制原因、有效期间、证据、批准人。只有人工批准的规则才能执行内部禁止推进；从投诉表导入的原始词条默认是待核实线索。

新建产品、发起审核、修改拟售文本时，自动匹配当前团队可见的案例。展示“命中了哪个对象、哪个市场、哪条历史证据”，不以无解释的红色总分代替。

对于新案例，反查已关注或有有效审核的产品，产生复核待办。先走确定的商品/权利号/品牌词关系；模糊图片候选须人工确认关联，避免同一张通用产品图使大量产品被误封。

## 9. 旧表导入与以后同步

先用现有 Excel 做一次可校对的历史迁移，再接钉钉增量。导入走“解析 → 预览 → 修正映射 → 确认”，确认前展示有效记录、疑似重复、图片关联不明和字段冲突。

具体处理规则：

1. 按工作表/版块定义映射；保存原文件、工作表、单元格或版块位置、导入批次与源记录标识。
2. 图片按 drawing 锚点及覆盖区域关联；一对多保留，歧义进入人工校对。不能通过图片文件排列顺序配行。
3. “北美/欧洲”“全站”保留原文，精确市场未确认前不生成跨市场通用结论。“不建议欧洲上架”不能反推出“美国已通过”。
4. 旧记录“可以上架”保存为历史原结论，标记“待复核”，不直接授予现在的有效通过状态。
5. 关键词、产品标题、商标、权利人分开；日期按实际源格式解析；只有运营名字时不能伪造审核人。
6. 原文与标准化字段并存。冲突记录进入校对队列；历史邮件中包含的案件号、联系人与账号信息按权限展示和导出。
7. 同文件重复导入用文件哈希＋源位置幂等；更名或重新导出的文件不自动当作全新案例，使用稳定源 ID 或提示重复候选，不以行号跨文件强行合并。
8. 钉钉接入后，每个字段明确来源优先级：源表负责原始记录，KeywordIQ 负责标准化、审核和复核；不做一期双向同步。源记录变更生成新版本或冲突，不能覆盖已签署结论。

RISK-02a 与 02b 的线上表是否同源仍待确认；连接器从设计上支持多个数据源映射到案例库，避免押注只有一张表。

## 10. 数据与权限边界

### 10.1 最小逻辑实体

| 实体 | 用途 |
|---|---|
| 产品档案 / 产品版本 / 来源关联 | 内部研究对象、拟售材料版本、跨平台引用 |
| 关注与监测订阅 | 谁在关注什么、监测哪些指标与频率 |
| 观测 / 变化事件 | 来源事实与派生变化分离，均可追溯 |
| 风险案例 / 案例对象关联 | 历史经历、证据和匹配对象 |
| 检索任务 / 证据快照 | 外部查询、执行状态、花费、覆盖及返回结果 |
| 审核单 / 分市场审核结果 | 输入版本、检查范围、人工意见、业务决定 |
| 复核任务 / 审计记录 | 变更触发、处理人、前后版本与理由 |

这些是逻辑责任，不要求机械地一行对应一张新表。复用机会中心的证据、任务、审批和审计契约；该能力尚未实现时不能声称已复用其运行时。

### 10.2 隔离

当前用户私有关注不自动升级成全员共享。建议产品草稿默认私有，团队共享、审核协作与内部案例库以明确成员关系为边界。机会中心的 tenant 方案尚待评审；团队版落地必须先完成租户/团队成员与现有用户的映射，不能直接把全部现有账号归入同一公司。

共享采集只适用于授权允许复用的公开事实；采购证明、投诉邮件、案例、检索历史与审核意见按租户和可见范围隔离。附件链接、搜索摘要、导出和后台任务同样执行权限检查。

接上真实端点时再增加产品查看/编辑、风险查看、检索、审核与资料管理等权限，具体最小权限集合随实现定稿；不为仍然空白的占位功能提前制造无效权限点。

### 10.3 历史与性能

产品档案、审核与证据不跟随 ABA 三个月分区清理。ABA 引用保留做决策所需的最小证据快照、期次和批次，不能在原分区清理后只剩一个失效链接；按数据授权执行保留和删除政策。

初期沿用 PostgreSQL 与既有后台调度模式；持续网络调用不能占用数据库事务。队列应有租约、重试、幂等与失败记录。大型外部检索服务是否拆分由实际并发和成本决定，不预先建设全量全球专利索引。

只对用户选择的产品做深度监测。列表匹配内部已审核规则、读取缓存摘要；外部付费查询在提交时执行，事先显示本次预计调用量。同一来源事实能否跨用户复用由授权范围决定。

## 11. 交付顺序与完成条件

| 阶段 | 交付内容 | 完成条件 |
|---|---|---|
| A：内部工作流 | 产品档案、旧表导入校对、案例匹配、人工审核、分市场结论与版本历史；复用现有竞对发现数据 | 一条真实历史审核可完整还原；一个新产品可提交、补证、出具结论、变更后复核；权限隔离通过 |
| B：上线必做风险能力 | 文字商标正式检索、外观检索、证据快照、费用与失败状态；审核页面比对 | 两类能力都有真实数据源与覆盖说明，在目标市场样本上验收。仅完成 A 不代表 RISK-01 完成 |
| C：持续监测增强 | 价格/BSR/评分等正式来源，需求变化事件，权利状态更新、案例反向复核和通知 | 每个规则都有可比较观测、口径与缺期行为；重复采集不重复提醒 |
| 后续 | 图形商标近似检索、更多法域/风险类型、同款候选、批量复核与更深的机会中心联动 | 逐项验证数据、授权与实际使用价值 |

阶段 B 的数据可行性验证应与 A 同时开始，避免内部工作流完成后才发现外观接口不可用。原 PRD 的“上线前必做”保持；如最终只能提供跳转＋人工上传，那是验收范围变更，需要业务明确接受，不能默认为等价交付。

不沿用报价表的旧人天作为本方案承诺，也不据网页套餐价估算 API 成本。完成接口样本验证后，按“监测对象数×频次×单次成本＋检索量＋存储/导出成本”分别测算。

### 关键验收场景

1. 同一产品在 GB 不建议上架，US 未核查：不得显示“US 已通过”或全局“安全”。
2. 已通过 v1 的产品更换包装和品牌：v1 历史仍在，当前 v2 显示待复核。
3. 外部来源超时与成功无命中：界面、导出和审核关卡均能区分。
4. 第三方只有月销量估算：不出现真实日单量、不触发连续 3 天出单规则。
5. 一次浏览没有见到商品：不判下架；首次卖家上报不批量制造新发现。
6. 新案例命中已审产品：只生成对应市场/对象的复核候选，不能全站批量否决。
7. 原表图片覆盖多行、2023 表并排多个案例：歧义可见，不静默错配。
8. 案例附件、检索历史、审核单和导出均无法跨团队访问。
9. 同文件重导、同查询重试、同批观测重放：不重复建案、签结论或生成事件；计费重试行为另与供应商验证。
10. ABA 原始期次退出热窗口：历史审核仍能解释当时使用的市场证据与口径。

## 12. 进入实现前需要确认的事项

- 产品库与案例库的共享范围：个人、团队或部门；谁负责风险审核，谁负责业务放行。
- 钉钉的正式来源表、稳定记录 ID、字段及附件权限；两份 Excel 分别对应哪些线上来源。
- 外观检索服务的可调用 API、目标市场覆盖、状态时效、合法缓存/展示/导出权限和预算。
- RISK-01 的“图形外观”按现有文义作为产品外观设计；纯图形商标检索若也要求上线必做，应额外列为明确验收项。
- FAV 的真实订单来源是否存在；若不存在，是否接受单独标注的第三方估算指标。

这些问题不妨碍先评审页面、对象关系和审核流程，但涉及的能力不能在实现和验收时通过默认值悄悄补齐。
