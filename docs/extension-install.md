# KeywordIQ 竞对采集插件：安装与使用

给运营看的一页说明。插件在 Amazon 卖家的店铺全品列表页上采集商品 ASIN，并上报到 KeywordIQ。

## 开始前确认

- 你的 KeywordIQ 账号有「竞对监控」权限（运营、分析师角色默认有）
- 要采集的卖家**已经在 KeywordIQ「竞对监控」里关注**，否则上报会被整体拒绝
- 你的 Amazon 账号收货地址设成目标市场（US / GB / DE）。Amazon 会按收货地址过滤店铺商品，地址不对会大量漏采
- 浏览器用 Chrome（或基于 Chromium 的 Edge）

## 一、安装

1. 收到 `keywordiq-competitor-collector-vX.Y.Z.zip` 后，**解压到一个固定的文件夹**，装好后不要删除或移动它（例如 `文档/keywordiq-collector`）
2. Chrome 地址栏输入 `chrome://extensions`，打开右上角「开发者模式」
3. 点「加载已解压的扩展程序」，选择刚才解压出来的文件夹
4. 点工具栏的拼图图标，把「KeywordIQ 竞对采集」固定出来

Chrome 启动时可能提示「停用开发者模式的扩展程序」，选保留即可。

## 二、首次设置

点插件图标打开设置页，填三项：

| 设置项 | 填什么 |
|---|---|
| API 地址 | `https://key.liangtong.online` |
| 网页地址 | **留空** |
| 单次上报条数上限 | 向管理员确认，默认 `200` |

点「保存」，Chrome 会弹出权限对话框，**必须点「允许」**。

然后在浏览器里**打开并登录** `https://key.liangtong.online`，回到设置页点「从网页同步令牌」。之后令牌过期时插件会自动重新同步，前提是这个网页的登录还在。

同步失败时的提示：

| 提示 | 该做什么 |
|---|---|
| 没找到网页 | 打开 KeywordIQ 网页，再点同步 |
| 尚未登录 | 在网页里登录，再点同步 |
| 未授予权限 | 重新点「保存」并允许权限，再点同步 |

## 三、采集与上报

1. 打开已关注卖家的 Amazon 店铺全品列表页（链接里带 `me=` 的页面）
2. 页面右上角出现悬浮面板，点「采集本页」
3. 店铺有多页就翻页，每页都点一次「采集本页」，结果按 ASIN 去重合并
4. 所有页面采完后，点一次「提交上报」

要点：

- **必须采完所有页再提交一次**。分多次提交会让第一次提交单独成为该卖家的基线，之后采到的存量商品会被误判成「新发现」
- 提交失败（网络、令牌过期）时已采集的内容不会丢，处理好后直接再点「提交上报」
- 只有提示「清空已采集，重新开始」相关的冲突时才需要清空重来
- 「新发现」为 0 只表示已采集范围内没有新发现，不代表这家店没有上新

## 四、常见问题

| 现象 | 原因与处理 |
|---|---|
| 未识别到任何商品，页面结构可能已变化 | Amazon 页面改版，联系管理员 |
| 撞到条数上限，采集与提交被锁定 | 这家店商品数超过单次上限，只能清空放弃这次采集，联系管理员 |
| 提交时报 422 或提示条数超限 | 设置页的条数上限与服务端不一致，向管理员确认后修改 |
| 移动或改名了插件文件夹 | 重新按「安装」加载；固定 ID 后设置一般会保留 |

## 五、升级

收到新版本 zip 后，把内容**覆盖解压到原来的文件夹**，再到 `chrome://extensions` 点该插件的「重新加载」按钮。

## 管理员：打包与发版

```bash
cd extension
pnpm install
pnpm run pack        # 构建并产出 release/keywordiq-competitor-collector-v<版本>.zip
```

- 版本号在 `manifest.json` 与 `package.json` 两处，必须一致（`test/manifest.test.ts` 会拦）
- `manifest.json` 里的 `key` 是公钥，用来固定扩展 ID（`deeognacliaabdllgfhofccnfipmmidl`）。对应私钥不入库，
  只在有需要（例如将来上 Chrome Web Store 沿用同一 ID）时才用到，请妥善保管，丢了不影响现有安装
- 发版前先改两处版本号，再跑 `pnpm run pack`，把 `release/` 下的 zip 发给运营
- `release/` 已被 gitignore
