# 语义层与工具契约

## 1. 为什么需要它

参考《[淘宝百亿补贴数据分析助手 Agent 实战](https://mp.weixin.qq.com/s/BpsscOnYq-DWsb_DrID8hA)》，关键不是让 LLM 直接写 SQL，而是先将自然语言映射到受治理的指标、实体和工具。否则模型会猜字段、混淆口径并生成不可追溯结论。

KeywordIQ V0/V1 不开放任意 NL2SQL；采用业务语义层和产品定义的受控查询能力。

```text
输入 / Signal → 意图与实体标准化 → 语义层 → 受控工具计划
             → 参数/权限校验 → 证据快照 → 结构化结论
```

## 2. 需要版本化的资产

| 资产 | 内容 |
|---|---|
| 实体目录 | 关键词、ASIN、品牌、类目、站点、Signal、机会及其关系/可用范围 |
| 指标字典 | 定义、来源、适用市场/窗口、版本、缺期处理、禁止混用的近义指标 |
| 工具契约 | 输入/输出 schema、权限/租户范围、最大结果集、来源、失败码、只读/草稿属性 |
| 规则与模板 | Signal 规则、验证计划、风险提示、结论 schema；启用前人工审核 |
| 证据血缘 | 结论到工具、参数、批次/快照、转换规则的显式链路 |

例如，Amazon 排名、点击份额、转化份额、Google Trends 相对热度是不同指标，禁止被 Agent 合并为未定义的“需求分”。

## 3. 资产保鲜与影响追踪

语义资产不是一次性配置。每条指标定义、Signal 规则、工具契约和模板必须附带 `version`、`last_verified_at`、`valid_until`、`owner` 和状态（`active` / `needs_review` / `retired`）。

- 到期未复核的资产自动转为 `needs_review`；Agent 可引用但必须向用户显示“需复核”，不可生成高置信度结论。
- 每次引用资产生成证据时，证据快照记录资产 ID 与版本；资产失效后可反查受影响的 Signal、结论和机会档案。
- 被频繁退回、纠错或质量检查失败的资产触发复核；被稳定采用的资产仍必须在有效期内人工复核，不能以使用率替代治理。

## 4. 指标注册与机器校验

指标字典不是说明文字，而是可验收的注册资产。每项指标必须声明来源、计算表达式/规则、单位、适用范围、缺期处理、版本，以及与其他指标的数学关系或“不存在可验证关系”。

- 可分解指标须声明公式类型和因子；注册检查应验证因子经约分/聚合后与总指标一致，例如 `总额 = 曝光 × 转化率 × 客单价`。
- 不可分解指标（如排名、份额）须声明允许比较的窗口、分母/样本限制及禁止混用的指标；在 CI 或指标任务中校验数据类型、范围、分母非零和时间对齐。
- 校验失败的指标版本不能被 Signal 或 Agent 工具引用；历史结论保留原版本与失败状态，不静默改写。

## 5. Harness 闸门

每次执行依次校验：

1. 意图、实体、站点和时间窗是否可解析；
2. 指标、维度和作用域是否在字典允许范围内；
3. 租户和工具权限是否匹配；
4. 查询成本、结果集、超时和限流是否在预算内；
5. 证据是否完整，输出是否满足结构化 schema；
6. 若产物为草稿或潜在外部动作，是否已进入审批网关。

失败应返回可区分的澄清、不可用、权限不足、质量异常或需人工复核状态。

## 6. Trace 与评测

从 V0 起保存输入标准化、路由、工具调用/结果摘要、校验、证据引用、规则/模型版本和最终产物。Golden Cases 至少覆盖：正确 Signal 解释、缺期阻断、ASIN 覆盖范围、外部数据不可用、风险源未接入、越权/外部写操作拦截。

评测同时检查最终结论与过程：工具选择、证据忠实度、未知项声明、schema 合规和 Gate 拦截。
