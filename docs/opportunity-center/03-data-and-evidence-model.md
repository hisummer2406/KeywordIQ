# 数据与证据模型

## 1. 数据分层

```text
原始数据与授权连接器
  → 事实层（Amazon 导入、规范化对象）
  → 派生层（质量检查、指标、Signal）
  → 工作台层（机会、证据、任务、审批、反馈）
```

事实、派生结果和 LLM 结论必须分离：模型输出不能回写或改写事实层。

## 2. V0 逻辑实体

| 实体 | 最小责任 |
|---|---|
| `tenant` / `data_source` / `source_batch` | 隔离、来源授权和导入批次 |
| `signal` / `signal_evidence` | 可复现的规则输出与输入依据 |
| `opportunity` / `opportunity_subject` | 生命周期、对象、问题、目标和约束 |
| `evidence_snapshot` | 来源、参数、时间、原始摘要、转换与质量状态 |
| `expert_task` | 专家任务、输入快照、状态、产物和阻塞原因 |
| `decision` / `approval` / `action_draft` | 选项、审批、草稿与人工执行回填 |
| `feedback` / `outcome_review` / `audit_log` | 基线、回查、反馈和不可变审计 |

这是逻辑模型，不代表已确定的 ORM、迁移或表结构。

## 3. 隔离与存储

- 新增工作台数据必须带 `tenant_id`；`site` 仅是业务市场范围。
- 图片和附件进入对象存储；数据库只保存元数据、权限范围、哈希和引用。
- 每个证据快照至少记录来源/授权方式、查询参数、采集和分析时间、原始摘要/引用、转换规则、质量状态、工具/规则/模型版本。
- 外部数据不能覆盖 Amazon 原始事实；冲突必须并列保存并对用户可见。

## 4. 数据质量门槛

在导入质量校验通过后才计算 Signal。错期、缺期、重复、来源过期或指标版本不匹配时，生成数据异常/阻塞，而不是 Opportunity 或 Risk。

## 5. 数据源边界

V0 只允许质量通过的现有 Amazon 数据与人工附件。SP-API、Keepa、SellerSprite、Google Trends、商标、专利等均须逐个完成授权、覆盖、成本、缓存、再展示、删除义务、限流和失败降级评审后才可作为证据。
