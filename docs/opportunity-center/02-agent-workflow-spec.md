# Agent 工作流规范：受控多专家编排

## 1. 原则

Agent 不是多个自由聊天机器人，而是由状态机驱动、以证据为输入、以结构化产物为输出的受控工作流。确定性规则负责计算；LLM 负责澄清、计划、工具选择、解释冲突和生成草稿。

```text
输入 / Signal → 主理 Agent → 专家任务 DAG → 证据包 → 决策建议 → 审批网关
```

## 2. 角色契约

| 角色 | 目标 | 输出 | 禁止事项 |
|---|---|---|---|
| 主理 Agent | 澄清、计划、调度与综合 | 问题定义、任务 DAG、阶段结论、待批准动作 | 绕过风险/审批；直接外部写操作 |
| 机会发现专家 | 提出可验证候选与反例 | 触发证据、候选、适用范围 | 将 Signal 直接称为机会/利润 |
| 市场验证专家 | 判断外部需求、季节性、区域差异 | 独立证据、冲突、验证缺口 | 把相对热度当销量/需求 |
| 商品与竞争专家 | 分析 ASIN、关键词、份额与竞争变化 | 比较、走势、假设与反证 | 编造价格、库存、销量 |
| 供应链可行性专家 | 生成可人工核验的供应假设 | 需求包、约束、询盘草稿 | 自动询盘、比价、谈判、采购 |
| IP 风险专家 | 暴露风险和覆盖缺口 | 风险清单、复核建议 | 法律结论；未接数据时宣称低风险 |
| 决策/复盘专家 | 比较选项并定义验证/回查 | 选项、基线、计划、复盘 | 自动改变规则或长期记忆 |

## 3. 执行状态

机会：`草稿 → 待澄清 → 发现中 → 验证中 → 风险待核查 → 待决策 → 已批准推进 / 退回补证 / 观察中 → 已否决 / 已归档`。

专家任务：`queued → running → blocked | needs_review | completed | failed`。

“风险待核查”不是低风险；“已批准推进”只允许内部验证，不授权任何外部经营或交易动作。

## 4. 输入、上下文与输出

每个任务读取版本化的“机会上下文包”，而不是完整聊天记录：问题、对象、站点、约束、已批准证据索引、已完成任务、当前阶段、权限和预算。

所有专家输出必须符合结构：`claim`、`evidence_refs`、`scope`、`uncertainties`、`counter_conditions`、`recommended_next_step`。不能关联有效证据的输出只能返回阻塞或澄清请求。

## 5. 运行时安全

- 异步 worker 执行长分析与连接器调用；不得阻塞 FastAPI 请求路径。
- 每项任务带幂等键、超时、重试上限、成本/结果集上限和审计 trace。
- 工具注册只声明只读/草稿/外部写三类能力；V0/V1 仅前两类，草稿仍须审批。
- 失败时降级为“数据不可用/需要澄清/需人工复核”，不输出假设性事实。
